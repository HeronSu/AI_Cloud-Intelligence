# 高级权限管理

# 1.umask权限掩码

## umask概念与计算 

案例引入
```bash
# 在Linu系统中，可以发现一种情况
[root@CentOS ~]# ll -d /opt
drwxr-xr-x. 2 root root 20 Sep 21 20:42 /opt

# 在没有设置权限的情况下，默认在root用户下创建目录权限默认为755，文件的默认权限为644
[root@CentOS opt]# ll
total 4
-rw-r--r--. 1 root root 2548 Sep 21 20:42 passwd
[root@CentOS opt]# mkdir inform
[root@CentOS opt]# echo hahahah> index.txt
[root@CentOS opt]# ll
total 8
-rw-r--r--. 1 root root    8 Sep 24 10:25 index.txt
drwxr-xr-x. 2 root root    6 Sep 24 10:25 inform
-rw-r--r--. 1 root root 2548 Sep 21 20:42 passwd
```
> [!tip]
> 出现上面这种情况，是由umask权限掩码所决定的

- umask权限掩码：是用来**决定新建文件或目录时默认权限**的一个“权限屏蔽码”。它的作用是**从基准权限中“减去”某些权限。


**核心计算公式**
- 文件：基准权限 `666` - umask = 实际权限
- 目录：基准权限 `777` - umask = 实际权限

- 在Linux系统中，有一个命令`umask`，用来输出**当前 Shell 会话**的 umask 权限掩码。以此为例，来计算实际的root用户的目录和文件权限
```bash
[root@CentOS ~]# umask
0022
```

- 这里的输出结果为`0022`，这里先不管前面的0，当前root用户的umask权限掩码为022。
```text
目录默认权限：777-022=755 即rwxrw-r-x-r-x
文件默认权限：666-022=644 即rw-r--r--
```


## 修改umask

- 临时修改umask
```bash
# 在当前终端执行下列命令
umask <number>

# 但是这个只在当前终端临时生效，一旦当前终端被关闭了，再打开新的终端，就无法生效了
```


- 要求：文件是600 目录是700 
	- 这里如果以文件的实际权限来反推umask，得到的结果为066，然后实际去计算目录777-066=711，与实际权限不一致
	- 如果umask值没有设置好，最终会导致文件和目录的默认权限计算出来的结果不一样
>[!tip]
>如果要计算umask,根据需求，以目录权限为准先进行反推得到umask，然后文件计算得到的结果也能和实际权限结果保持一致

- 再次计算
```text
# 以目录为基准，反推umask
777-700=077

# 通过计算出来的umask来进行计算文件实际权限
666-077=600
```

>[!caution]
> 这里进行计算，并不是常规的数学计算，需要将umask取反然后求与运算，这里不做介绍。

为了方便计算，提供下列方法，当通过目录为基准算出来的umask中带有奇数时，进行下列操作
- 7 (`rwx`) -1 = 6 (`rw-`)
- 5 (`r-x`) -1 = 4 (`r--`)
- 3 (`-wx`) -1 = 2 (`-w-) 
- 1 (`--x`) -1 = 0 (`---`)  

>由于文件默认基准权限就不存在`x`权限，将所有奇数减去1即可。减1的目的，就是消灭 `x` 位，让每一位数字都小于等于偶数，这样相减时就不会发生八进制借位了！
```text
666-(077-011)=600
```


- 全局修改：即针对所有用户设置umask权限掩码
```bash
# 关键文件
/etc/bashrc

# 具体字段如下，过滤关键字umask
if [ $UID -gt 199 ] && [ "`/usr/bin/id -gn`" = "`/usr/bin/id -un`" ]; then
    umask 002
else
   umask 022
fi
```


- 用户自己修改
```bash
# 关键文件
~/.bashrc

# 修改完相关内容后，保存并退出，并加载该文件
source ~/.bashrc
```




# 2.ACL访问控制列表

> [!note]
> 场景：某文件的相关权限如下，现在有两个用户，分别为user1和user2，现在需要给他们写权限。那大致有以下几种解决办法
> `-rw-r--r--. 1 root root 2548 Sep 21 19:47 /etc/passwd`
> - 将user1和user2加入root组，然后修改该文件拥有组的权限为`rw-`
> - 将该文件权限的其他人权限改为`rw-`

**上面这两种解决办法存在很大的风险**

> [!warning]
> - 首先对于系统核心文件或者是重要文件来说，修改权限要慎之又慎
> - 方案2的问题
> 	- 如果一旦将这两个用户加入root组，那么这个系统上的属于root用户组的文件和目录，这两个用户都有操作权限了，这十分危险
> 	- 如果root用户组中还有别的用户，那么别的用户也会拥有上面提到的相关权限，权限波及很大，而且一旦其他用户误操作，很可能会对文件造成损坏
> - 方案2的问题
> 	- 系统核心文件和重要文件，如果其他人有了写的权限，那么不论是什么用户，都可以随意对该文件进行篡改。


- **ACL(Access Control List)**：访问控制列表，主要是针对ugo（拥有人，拥有组，其他人）权限的扩展和补充，即ACL可以针对**特定的单个用户或特定的用户组精准赋权**。


> [!tip]
> ACL权限的出现实际上是为了解决基本权限不足的问题


## 设置、查看与删除ACL

- 主要语法
```bash
# 主要格式
setfacl -m [u|g|o]:<username|groupname>:[rwx] <file or directory>
```


- `setfacl -m` 设置和修改 ACL 权限，具体权限表示如下：

| 描述              | 功能               |
| --------------- | ---------------- |
| 给指定用户设置 ACL 权限  | `u:mary:rx file` |
| 给文件拥有人设置 ACL 权限 | `u::rwx file`    |
| 给指定组设置 ACL 权限   | `g:it:rwx file`  |
| 给文件拥有组设置 ACL 权限 | `g::rwx file`    |
| 给文件其他人设置 ACL 权限 | `o::rx file`     |
| 设置掩码值           | `m::rw file`     |


- 需求：要求user1对`/data`目录有`rwx`权限，其他人依然只有`r-w`权限
```bash
# 设置前权限
[root@CentOS ~]# ll -d /data/
drwxr-xr-x. 2 root root 6 Sep 29 20:41 /data/

# 设置访问控制
setfacl -m u:user1:rwx data/

# 查看目录的权限，可以看到多了一个+号，说明有了设置了ACL权限，此时查看权限不能再单一看前面的
[root@CentOS ~]# ll -d /data/
drwxrwxr-x+ 2 root root 6 Sep 29 20:41 /data/
```

- 查看ACL权限使用下列命令：`getfacl`
```bash
# 主要语法
getfacl <path|file or directory>

# 查看上述文件的ACL权限
[root@CentOS ~]# getfacl /data/
getfacl: Removing leading '/' from absolute path names
# file: data/   # 文件或者目录名
# owner: root   # 拥有人和用拥有组，与上面的输出显示一致
# group: root 
user::rwx
user:user1:rwx   # 这里拥有人多了user1，对应权限为rwx
group::r-x
mask::rwx
other::r-x

# 这里的拥有组权限有了w权限，但是上面查询到的并没有
drwxrwxr-x+ 2 root root 6 Sep 29 20:41 data/
```

- 下面进行一系列测试

- 删除ACL权限
```bash
# 删除ACL
setfacl -x [u|g|o]:<username|groupname> <file or directory>

setfacl -x u:username <file or diretory>    
setfacl -x g:groupname <file or diretory>

# 删除刚才文件的ACL权限
setfacl -x u:user1 /data/

# 再次查看是否删除
[root@CentOS ~]# getfacl /data/
getfacl: Removing leading '/' from absolute path names
# file: data/
# owner: root
# group: it
user::rwx
group::r-x
mask::r-x
other::r-x

# 但是此处仍然有+号
[root@CentOS ~]# ll -d /data/
drwxr-xr-x+ 2 root it 18 Sep 29 21:27 /data/
```

- 如果想彻底去掉所有的ACL权限，执行下列命令
>这个一般不要轻易使用，会去掉所有ACL权限
```bash
setfacl -b <file or directory>

# 彻底去掉所有的ACL权限
setfacl -b /data/
[root@CentOS ~]# ll -d /data/
drwxr-xr-x. 2 root it 18 Sep 29 21:27 /data/
```


## 匹配优先级与mask

- ACL权限的匹配优先级
	1. 用户的ACL权限
	2. 用户权限
	3. 用户组的ACL权限
	4. 用户组的权限
	5. 其他人权限
> [!important]
> **只要有ACL权限，则优先级最高匹配**



- mask的权限控制着ACL的有效权限
```bash
# 设置mask掩码
setfacl -m m:r-x /data/
getfacl /data/

getfacl: Removing leading '/' from absolute path names
# file: data/
# owner: root
# group: it
user::rwx
user:user1:rwx                  #effective:r-x 最高权限不超过r-x
group::r-x
mask::r-x
other::r-x
```

> [!tip]
> 一般来说，不会通知mask的形式来去设置文件或者目录的ACL，不如直接设置更加简洁




## ACL权限继承

- 所谓ACL权限继承，是通过设置ACL权限来自动把这些默认ACL规则复制给新建的对象。
> [!important]
> 主要应用场景：在某些共享存储的场景下，例如NFS共享，如果有一个`/share`目录希望团队里的 user1 和 user2 在里面新建的任何文件，都自动拥有读写权限。  

- 在上述设置ACL的基础上，再次增加一个参数，赋予继承的功能
```bash
setfacl -m -d u:user1:rwx /shared
```

- 需求：`/data`目录下新创建的文件都会继承目录的acl权限，所有新的文件都会有user1用户的`rw`的acl权限。
```bash
setfacl -m -d u:user:rw /data
```

# 3.三大特殊权限
> [!tip]
> 特殊权限属于系统的一些机制，在实际工作中，这些特殊权限被使用的较少，但是需要了解
 
 - Linux中的特殊权限要用于解决“**普通用户需要临时获得更高权限来执行特定操作**”或“**在共享目录中保障文件安全**”这两类场景。

```bash
# 类似这里的文件权限，这个文件权限中有s的权限，并不是常规的rwx
[root@CentOS ~]# ls -l /usr/bin/passwd
-rwsr-xr-x. 1 root root 33600 Apr  7  2020 /usr/bin/passwd
```



## suid特殊权限

- 对目录：没有任何的意义
- 对文件：文件拥有suid权限，则执行这个文件时是以文件的拥有人的身份去执行的，即任何人只要执行该命令时得到命令拥有人的权限。
>[!important]
> 仅仅对二进制可执行文件（命令）有效果，对于自定义脚本没有意义。

```bash
# 这个文件是属于二进制可执行文件，该文件中有suid权限，即任何用户执行passwd拥有root权限
[root@CentOS ~]# ls -l /usr/bin/passwd
-rwsr-xr-x. 1 root root 33600 Apr  7  2020 /usr/bin/passwd
```

### Example

- 反例：一个无任何权限的文件`/etc/shadow`
```bash
[root@servera etc]# ll /etc/shadow
----------. 1 root root 1307 Jul 15 16:26 /etc/shadow
```

> [!tip]
> 如上所示，`/etc/shadow`文件没有任何权限，为什么root用户也可以修改？
>答：文件的拥有人可以强制修改自己的文件，其他用户不行。

- 对于普通用户来说，是可以修改自己的密码的，但是密码信息又可以被写入到`/etc/shadow`中，原因就是passwd这个命令对应的二进制可执行文件的suid权限得到的效果，因为使用命令`passwd`暂时拥有了root用户身份，从而将密码信息写入到`/etc/shadow`文件中


- 展开这个案例来进行说明：修改密码，对于所有用户来说，都可以修改自身的密码，但是只有root用户可以修改除自己外的指定用户密码。
```bash
# 指定其他用户
[user1@CentOS ~]$ passwd user
passwd: Only root can specify a user name.

```

- 但是还有一种情况，当普通用户指定自己来修改密码，依然无法进行修改
```bash
[user1@CentOS ~]$ passwd user1
passwd: Only root can specify a user name.
```

- `passwd`命令的实现逻辑大致是这样的。为了安全，Linux 选择了最简单粗暴的规则：**只要带了参数，就一律视为特权操作，直接要求 root 权限。**
```c
if (argc > 1) {
    // 带了参数（比如 passwd user1）
    // 认为用户想指定修改某个用户的密码
    if (getuid() != 0) {
        // 检查当前真实用户是不是 root
        // 如果不是 root，直接报错并退出！
        fprintf(stderr, "只有 root 用户才可以指定用户名。\n");
        exit(1);
    }
    // 如果是 root，继续执行修改逻辑...
} else {
    // 没带参数（直接输入 passwd）
    // 认为用户想修改自己的密码
    // 获取当前真实用户，然后走修改自己密码的流程...
}
```
> [!caution]
> 如果普通用户如果允许`passwd`后面加上参数会有什么后果？
> 假设允许 `user1` 执行 `passwd user1`，程序就必须去区分：这到底是 `user1` 自己搞错了，还是 `user1` 试图越权修改别人的密码？程序判断会有问题，而且也很有风险



- 查看文件是否具有`suid`权限
	- 如果文件的拥有人的x栏变成了小写的`s`或者大写的`S`，表示具有suid的权限。
	- 如果是小写的s，说明这个文件的拥有人有x权限。
	- 如果是大写的S，说明文件的拥有人没有x权限。
```bash
# 尝试去掉拥有人的x权限，观察权限位的变化情况
[root@CentOS ~]# ll /usr/bin/passwd
-rwsr-xr-x. 1 root root 33600 Apr  7  2020 /usr/bin/passwd
[root@CentOS ~]# chmod u-x /usr/bin/passwd

# 去掉后变成了rwS
[root@CentOS ~]# ll /usr/bin/passwd
-rwSr-xr-x. 1 root root 33600 Apr  7  2020 /usr/bin/passwd
```


- 赋予suid权限，这里的4就是代表suid权限
	- 基于字符：**`chmod u+s 文件`**
	- 基于数字：**`chmod 4xxx 文件`** 例如：chmod 4755



## sgid特殊权限

- 对文件：文件拥有suid权限，则执行这个文件时是以文件的拥有组的身份去执行的。仅仅对二进制可执行文件（命令）有效果，对于自定义脚本没有意义。
- 对目录：目录具有sgid权限，则在这个目录下创建的新的文件都会继承目录的拥有组的身份。

- 主要呈现，在拥有组权限位看到小写`s`或者大写`S`，就表示具有sgid特殊权限，区别在于是否拥有x权限，相关解释同上。
```bash
[root@CentOS ~]# ll /usr/bin/write
-rwxr-sr-x. 1 root tty 21280 Jan 21  2021 /usr/bin/write
```

- 赋予sgid权限，这里的2就是代表sgid权限
	- 基于字符：**`chmod g+s 文件`**
	- 基于数字：**`chmod 2xxx 文件`**



## sticky(sbit)粘性权限

- 对文件：没有任何意义
- 对目录：目录具有sbit权限，则在这个目录下，只有用户自己才可以修改自己的文件和重命名

- 判断是否具有sticky粘性权限，看的是其他人权限位是否有小写`t`或者大写`T`，区别在于是否拥有x权限，同上解释。
```bash
[root@CentOS ~]# ll -d /tmp/
drwxrwxrwt. 10 root root 4096 Oct  8 11:20 /tmp/
```

> [!note]
> 主要应用场景：对于某一个公共目录，或者说是共享目录，团队合作各自负责各自的部分，相互之间不能干扰，只有用户拥有人和root用户可以删除文件，用户无法删除其他用户的文件。


- 赋予sbit权限，这里的1就是代表sbit权限
	- 基于字符：`chmod o+t <file>`
	- 基于数字：**`chmod 1xxx <file>`**

>[!tip]
>总结
> - 如果文件具有特殊权限，小写的字母都表示这个文件有x权限，大写的字母表示这个文件没有x权限
> - 所有文件权限的权限位实际上是四位，算上特殊权限的话，但是实际关注的话还是以常规权限居多
> - suid和sgid系统自身使用的较多，但是sbit权限实际用的话很有场景



# 4.文件底层属性

- 所谓的文件底层权限，实际上一类隐藏权限
> [!tip]
> 如果说`chmod`是给文件加了一把带密码的锁，那么`chattr`就是直接把文件焊死在保险箱里--即使是root用户，也无法随意修改或者删除

- 核心命令`chattr`，语法格式如下
```bash
chattr [+-=] [属性] 文件或目录
```

- `lsattr`用来查看文件的底层属性
```bash
# 没有设置文件底层属性时，文件权限会全部显示为空
[root@CentOS data]# lsattr test.txt
-------------------- test.txt

# 设置了底层属性时，文件权限会显示一个i
[root@CentOS data]# lsattr test.txt
----i--------------- test.txt

```

> [!important]
> 主要掌握`chattr`三个核心的关键参数

---
**1. 防篡改、防误删**

- 关键参数：`+i`(immutable，不可变)
- 作用：文件一旦加上 `i` 属性，**谁都不能修改、删除、重命名、创建硬链接**。连 root 也不行！
```bash
# 设置文件加上i属性，并查看文件底层权限
chattr +i test.txt
[root@CentOS data]# lsattr test.txt
----i--------------- test.txt

# 尝试删除，移动，发现均不允许，即使是root用户也做不到
[root@CentOS data]# rm test.txt
rm: remove regular file 'test.txt'? y
rm: cannot remove 'test.txt': Operation not permitted
[root@CentOS data]# mv test.txt /opt/
mv: cannot move 'test.txt' to '/opt/test.txt': Operation not permitted

# 去除i属性
chattr -i <filename>
```

>[!tip]
> 应用场景：
> - 保护核心系统文件（如 `/etc/passwd`、`/etc/shadow`、`/etc/fstab`），防止被黑客篡改或自己手滑删掉。
> - 保护重要数据文件，防止误操作。

---
**2.日志防删**

- 关键参数：`+a`(append only，仅追加)
- 作用：只能往文件末尾追加内容（`>>`），**不能覆盖、不能删除、不能修改原有内容**。同样对 root 生效。

> [!important]
> 这里追加内容无法使用`vim`编辑器来进行编辑，只能使用`echo`来进行追加内容
```bash
# 添加a属性
[root@CentOS data]# chattr +a passwd
[root@CentOS data]# lsattr passwd
-----a-------------- passwd

# 在这个过程中，如果尝试保存文件，会产生很多临时文件，文件内容和原始文件一致
ls
passwd  passwd~  passwy~  passwz~
```

> [!tip]
> 应用场景：保护日志文件（如 `/var/log/messages`、`/var/log/secure`）。即使黑客拿到了 root 权限，也无法擦除自己入侵的痕迹。

---
**3.不更新访问时间**

- 关键参数： `+A`(no atime，不更新访问时间)
- **作用**：读取文件时，不更新文件的“最后访问时间”（Access Time）。


> [!tip]
> 应用场景：高并发服务器上，减少磁盘 I/O，提升性能（因为每次读文件都要写一次元数据）。



# 5.sudo提权

- sudo的配置文件路径
```bash
# 主配置文件
[root@rhel9 ~]# ll /etc/sudoers
-r--r-----. 1 root root 4328 Jan 19 2023 /etc/sudoers

# 主配置目录
[root@rhel9 ~]# ll /etc/sudoers.d/
total 0
```


- 针对于用户配置sudo，相关格式如下
```bash
root ALL=(ALL) ALL(最后这个ALL，代表可以执行的命令，这个意味着可以使用所有的命令)

# 用户 + 可以使用的机器，然后最后是使用的命令，命令之间用逗号隔开，并使用绝对路径
user rhel9=(root,zhangsan,lisi) /usr/bin/touch,/usr/sbin/useradd

# 允许user这个用户，在主机名为rhel9的机器上，以 root、zhangsan或 lisi这三个用户中任意一个的身份，去执行touch和useradd这两个命令。

user ALL=(ALL) NOPASSWD:ALL-------->不需要验证改密码
```


- 针对用户组配置sudo
```bash
%wheel ALL=(ALL) ALL
```


- 针对配置目录下的文件下配置sudo
```bash
[root@rhel9 sudoers.d]# pwd
/etc/sudoers.d

[root@rhel9 sudoers.d]# cat user2
user2 ALL=(ALL) NOPASSWD:ALL
```

-  对于有sudo提权的用户，使用相关命令时，会要求输入密码，输入密码后，在一段时间后该用户使用该命令不需要输入密码。同时，也可以在配置文件中写入`NOPASSWD`，不需要验证密码
