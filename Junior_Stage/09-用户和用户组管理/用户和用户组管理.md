# 1.用户和用户组

## Linux系统识别用户

- Linux用户**并不是看用户名**，对于每一个用户都有一个**唯一的**ID号,被称为UID。对于Linux来说，**系统识别用户是根据用户的UID识别的**，用户是根据用户名来识别的。
- 对于计算机系统而言，数字相较于文字来说，更加方便对用户进行识别，只能识别二进制的0和1，而数字可以利用进制转换来让计算机系统进行识别


## 超级管理员

- 在Linux系统中，UID为0的用户才是系统的超级管理员。root用户也不一定是超级管理员，除非它的UID为0。（用id命令查看）
```bash
id
uid=0(root) gid=0(root) groups=0(root) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
```

>[!tip]
>**Linux系统中，每一个用户都有一个唯一的ID号**，不能有多个UID为0的用户，也不可能出现多个UID相同的用户

  

## 用户与用户组概念及分类

- 用户：登录系统需要用户，运行程序需要用户，设置权限需要用户
- 用户组：多个用户的集合，一个用户必须要加入到某一个组中
- 用户的分类（根据UID的范围进行分类）
    - 系统超级管理员：UID为0的用户（一般情况下是root）
    - 系统用户：0<UID<1000，**通常系统用户不允许登录，允许登录服务进程，需要用户运行
	- 普通用户：UID>=1000,一般是由管理员手动创建的
>[!important]
>- 系统用户的目的就是用来管理服务，一旦系统被入侵，如果对应服务进程的拥有人为root，对应服务也会被黑。
>- 系统用户存在的意义就是为了防止系统被入侵后，获得最高权限进行危险操作，即使相关服务被入侵，获得服务的权限也不是root，而是对应服务的系统用户

```bash
# 例如这里通过安装httpd来演示
yum install -y httpd

# 查看一个名为apache的用户
[root@controller ~]# id apache
uid=48(apache) gid=48(apache) groups=48(apache)

# 这里与httpd相关的很多进程大多是apache才可以控制的，即拥有人是apache
[root@controller ~]# systemctl start httpd
[root@controller ~]# ps -aux |grep httpd
root         938  0.0  0.2  20292 11468 ?        Ss   10:37   0:00 /usr/sbin/httpd -DFOREGROUND
apache      2411  0.0  0.1  21772  7356 ?        S    10:38   0:00 /usr/sbin/httpd -DFOREGROUND
apache      2415  0.0  0.2 1538296 11088 ?       Sl   10:38   0:00 /usr/sbin/httpd -DFOREGROUND
apache      2416  0.0  0.3 1669432 13136 ?       Sl   10:38   0:00 /usr/sbin/httpd -DFOREGROUND
apache      2417  0.0  0.4 1538296 17220 ?       Sl   10:38   0:00 /usr/sbin/httpd -DFOREGROUND
root        2879  0.0  0.0 221796  2256 pts/1    S+   10:43   0:00 grep --color=auto httpd

```

- 用户数量的上限在`/etc/login.defs`文件中，该文件中有如下字段
```shell
# Min/max values for automatic uid selection in useradd(8)
#
UID_MIN                  1000    # 普通用户最小的UID为1000，最大的UID为60000
UID_MAX                 60000
# System accounts  
# 这里的范围按照1~999，只有使用命令创建的系统用户，符合下面这个范围，上面的httpd
SYS_UID_MIN               201    # 系统用户的最小UID为201
SYS_UID_MAX               999    # 系统用户的最大UID为999
```


- 每创建一个普通用户，被创建用户的UID就在原来基础上加1
```bash
[root@CentOS ~]# useradd user1
[root@CentOS ~]# useradd user2
[root@CentOS ~]# useradd user3
[root@CentOS ~]# id user1
uid=1001(user1) gid=1001(user1) groups=1001(user1)
[root@CentOS ~]# id user2
uid=1002(user2) gid=1002(user2) groups=1002(user2)
[root@CentOS ~]# id user3
uid=1003(user3) gid=1003(user3) groups=1003(user3)
```



- 用户组的分类（GID）
    - 私有组（属组）：一个用户必须要加入到一个用户组，这个用户组就是用户的私有组。
    - 附加组（公共组）：用户可以加入到多个拥有组中，这些拥有组就是用户的附加组

>[!tip]
>注：如果加入到其他的组中，你就可以访问这个用户组的文件




# 2.用户、UID及相关命令

## 用户信息文件

- 显示用户和UID对应关系记录在 `/etc/passwd`文件中
```bash
#　查看/etc/passwd相关权限
ll /etc/passwd
-rw-r--r--. 1 root root 2548 Jan 24 11:19 /etc/passwd
```


- 文件条目详解（**以冒号作为分隔**）
```bash
[root@centos network-scripts]# cat /etc/passwd |grep ^root
root:x:0:0:root:/root:/bin/bash
```
- 第一个栏位：用户名
- 第二个栏位：该用户是否需要身份验证，密码占位符（登录这个用户是否要验证密码，x表示要验证，没有x表示不需要验证）
> 可以利用这个方式，在救援模式下修改该文件，去掉密码占位符，然后重启，就不需要输入密码了
- 第三个栏位： UID，用户的UID是唯一
- 第四个栏位： GID，用户组的ID
- 第五个栏位： 描述信息，可以空白
- 第六个栏位： 用户的家目录
- 第七个栏位： 用户的登录shell


第一次登录到这个用户获得到的shell程序，有两类
- `/bin/bash` 用户可以登录，可以获得到shell
- `/sbin/nologin` 用户不可以登录，无法获得到shell


- 案例引入
```bash
# 修改某一个文件的拥有人和拥有组均为user1
chown user1:user1 hello.txt

# 查看文件权限
ll hello.txt
-rw-r--r--. 1 user1 user1 11 Sep 19 14:41 hello.txt

# 对user1用户进行删除
userdel -r user1
id user1
id: ‘user1’: no such user

# 再次查看文件的拥有人和拥有组，全部变化了原来user2的UID
[root@CentOS ~]# ll hello.txt
-rw-r--r--. 1 1001 1001 11 Sep 19 14:41 hello.txt
```


- 这里再次创建用户user2，创建一个用户名为`zhangsan·`，指定UID为1001
```bash
# 这里user2创建分为两种情况来看
# 1.user2为普通用户的第二个用户，在这之前只有user这一个普通用户，此时这个文件的权限又变回了user2

[root@CentOS ~]#id user2
uid=1001(user2) gid=1001(user2) groups=1001(user2)
[root@CentOS ~]# ll hello.txt
-rw-r--r--. 1 user2 user2 11 Sep 19 14:41 hello.txt

# 2.在user2再次被创建前，还有很多用户被创建了，那么此时user2的UID不再是1001
useradd user2
[root@CentOS ~]# id user2
uid=1005(user2) gid=1005(user2) groups=1005(user2)

useradd -u 1001 zhangsan
[root@CentOS mail]# id zhangsan
uid=1001(zhangsan) gid=1001(zhangsan) groups=1001(zhangsan)
[root@CentOS mail]# ll hello.txt
-rw-r--r--. 1 zhangsan zhangsan 11 Sep 19 14:41 hello.txt
```



- 关于UID的分配有以下几点
	- 如果被删除用户处在多个用户之间，那么这个被删除用户的UID在没有指定的前提下，默认是不会分配给新的用户的
	- 如果被删除用户处在末尾，即最后一个用户，那么这个被删除用户的UID无论在什么条件下，只要新用户被创建出来，该UID就会被分配给新用户


> [!important]
> Linux系统识别的是UID，而不是用户名本身
> - 如果一个文件的拥有人被删除，那么此时该文件的拥有人会显示为一个UID，即使再次创建该用户，除非不指定UID，该文件的拥有人仍然会显示为一个UID。
> - 如果系统创建用户，使用了原有用户的UID，那么新用户会继承原有用户的文件权限，比较危险，这意味着会拥有这些文件权限。




## 用户管理命令

>[!caution]
>用户创建、用户删除、用户修改，**只有管理员才有权限操作**

### useradd

>创建用户
```bash
# 主要命令格式
useradd <username> 

# 创建用户user1
useradd user1
```

这一条命令实际上执行了以下多个操作
- 创建`user1`用户
- 创建`user1`用户组
- 创建`user1`家目录
- 创建`user1`邮箱
- 将`user1`用户加入`user1`组中

  
> [!tip] 
> 注：
>- 创建一个`user1`用户，同时还会创建一个`user1`的组，这个组就是用户的私有组
>- `useradd`实际上是管理员创建的一个普通用户，如果没有特别指定用户的UID是多少，则这个用户的UID是`/etc/passwd`文件中UID最大的数+1，并且默认情况下，普通用户的UID是从1000开始计算


- `useradd`命令的选项，其实和`/etc/passwd`文件息息相关，文件中的每列都可以在创建用户的去指定它

| 常用选项（useradd） | 描述                   |
| ------------- | -------------------- |
| -u            | 指定用户的UID             |
| -o            | 复用UID，多个用户可以使用同一个UID |
| -g            | 指定用户的私有组（GID）        |
| -c            | 描述信息                 |
| -s            | 指定登录shell            |
| -d            | 指定家目录                |
| -G            | 指定附加组                |
| -M            | 不创建家目录               |
| -p            | 指定用户的密码（明文）          |

>eg：创建一个名为memeda11的用户，用户的UID为3010，用户的家目录`/opt/memeda11`，用户的描述信息为web user，用户的登录shell为`/sbin/nologin`，指定密码为redhat，指定附加组为zhangsan
```bash
useradd -u 3010 -d /opt/memeda11 -c "web user" -s /sbin/nologin -p redhat -G zhangsan memeda11
```

> [!tip]
> 分组的目的在于针对实际工作场景中的不同业务类型，需要被分为不同的组，以获得不同的权限


  
### userdel

> 删除用户
- 主要语法格式如下
```bash
# 删除用户
userdel <username>
```

> [!warning]
> `userdel <username>`确实是删除用户，但是删除的不干净，（如果uid和这个删除用户的uid是一样的）下一个新创建的用户会继承这个用户的所有的文件。

- 要想对一个用户完全删除干净，就使用下面的命令
```bash
# 删除用户的同时删除家目录和邮箱文件
userdel -r <username>
```

>[!tip]
> 注：一个用户创建出来，它会有家目录以及有它的邮箱同时创建默认是`/home`，邮箱文件在`/var/spool/mail`目录，和用户是同名的文件。

  

### usermod

> 修改用户的相关信息
- 常用选项

| 常用选项         | 描述                                          |
| ------------ | ------------------------------------------- |
| -l new_login | 修改用户的名称                                     |
| -u           | 修改UID                                       |
| -g           | 修改GID                                       |
| -G           | 指定附加组                                       |
| -aG          | 追加用户到其他附加组中                                 |
| -L(Lock)     | 锁定用户密码 （在/etc/shadow上添加了一个`!`导致加密后的字符串匹配不上） |
| -U(Unlock)   | 解锁用户密码                                      |
| -d           | 修改用户的家目录                                    |
| -m           | 家目录不存在就创建，和-md联合使用                          |
> 如果执行`usermod -G <groupname> <username>`的命令，会导致原有添加的组被覆盖掉，因此要添加另外一个参数

- 实例1：将`user1,user2,user11`加入it用户组
```bash
usermod -G it user
usermod -G it user1
usermod -G it user2
```


- 实例2：再次创建一个组为zhangsan，再将user1,user2,user11加入zhangsan用户组
```bash
# 创建一个组为张三
groupadd zhangsan

# 将用户添加到zhangsan这个组
usermod -aG user zhangsan
usermod -aG user1 zhansan
usermod -aG user2 zhangsan
```

- 这里建议如果要将用户添加至附加组或者追加其他的附加组，直接使用-aG，可以实现两个效果
```bash
# 单个追加
[root@CentOS ~]# usermod -aG webserver user2
[root@CentOS ~]# usermod -aG it user2
[root@CentOS ~]# id user2
uid=1002(user2) gid=1002(user2) groups=1002(user2),1235(webserver),1236(it)

# 多个组变量之间用逗号隔开，可以一次性将用户添加到多个组中
[root@CentOS ~]# usermod -aG webserver,it user2
[root@CentOS ~]# id user2
uid=1002(user2) gid=1002(user2) groups=1002(user2),1235(webserver),1236(it)
```
  

# 3.用户组、GID及相关命令

## 用户组信息文件

- 每个组拥有唯一的Group ID GID

- 用户组文件
```bash
[root@centos ~]# cat /etc/group |grep ^web
[root:x:0:](webserver:x:1235:user1)
```

- 第一个栏位： 组名称
- 第二个栏位： 组是否需要验证
- 第三个栏位：GID
- 第四个栏位： 组成员



## 用户组密码文件

- 用户组密码文件：**`/etc/gshadow`**

```bash
[root@centos ~]# ll /etc/gshadow
----------. 1 root root 862 Feb 14 13:59 /etc/gshadow
```

- 在文件中每一个条目的第二栏，若为`!`，则表示该组没有设置密码；反之，则为加密后的密码


  

## 用户组管理命令

### groupadd

>[!warning]
>注意：默认不指定GID的话，组的GID是以`/etc/group`文件中GID最大的数+1作为组的GID

- 实例：创建一个名为it的组，指定GID为2000
```bash
[root@centos ~]# groupadd -g 2000 it

[root@centos ~]# cat /etc/group | grep ^it
it:x:2000:
```




### groupdel

- 删除组，主要用法如下
```bash
# 主要语法
groupdel <groupdel>

[root@servera ~]# groupdel memeda04
groupdel: cannot remove the primary group of user 'memeda04'

```

> [!tip]
> - 如果这个组是用户的私有组，则无法删除这个组
> - 如果一个组有其他的成员，则也无法删除这个组
 

  

### groupmod

- 修改组的相关信息，这里只介绍两个选项，如果有其他的需要，自行查看帮助
```bash
# 修改组的GID
[root@CentOS ~]# cat /etc/group | grep ^it
it:x:1002:user1

groupmod -g 1235 it
[root@CentOS ~]# cat /etc/group | grep ^it
it:x:1235:user1

# 修改组名
[root@CentOS ~]# cat /etc/group | grep ^it
it:x:1235:user1

groupmod -n webserver it
[root@CentOS ~]# cat /etc/group | grep ^web
webserver:x:1235:user1
```



### gpasswd & newgrp

- 主要用法如下
```bash
# 为用户组设置密码或者修改密码
gpasswd <groupname>

# 实例：为it组设置密码
gpasswd it

Changing the password for group it
New Password:
Re-enter new password:
```

```bash
# 添加用户到组
gpasswd -a (username) (groupname)

# 删除组内的用户
gpasswd -d username groupname

[root@CentOS ~]# id user2
uid=1002(user2) gid=1002(user2) groups=1002(user2),1235(webserver),1236(it)
[root@CentOS ~]# gpasswd -d user2 webserver
Removing user user2 from group webserver
[root@CentOS ~]# gpasswd -d user2 it
Removing user user2 from group it
[root@CentOS ~]# id user2
uid=1002(user2) gid=1002(user2) groups=1002(user2)

# 设置组的管理员
gpasswd -A username,.. groupname
```


- **`newgrp <groupname>`** 登录到用户组，只是临时登录到组中，临时拥有组的权限，此时附加组临时变成了私有组
```bash
# user1用户临时拥有该权限
[root@CentOS ~]# su - user1
[user1@CentOS ~]$ id user1
uid=1001(user1) gid=1001(user1) groups=1001(user1),1235(webserver)
[user1@CentOS ~]$ newgrp it
Password:
[user1@CentOS ~]$ id
uid=1001(user1) gid=1236(it) groups=1236(it),1001(user1),1235(webserver) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023

# 这里退出并没有退出用户，而是退出了it组
[user1@CentOS ~]$ exit
exit
[user1@CentOS ~]$ id
uid=1001(user1) gid=1001(user1) groups=1001(user1),1235(webserver) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023


# 将user3用户加入it组，再次临时登录到it组，发现不需要输入密码
[root@CentOS ~]# id user3
uid=1003(user3) gid=1003(user3) groups=1003(user3),1236(it)
[root@CentOS ~]# su - user3
[user3@CentOS ~]$ newgrp it
[user3@CentOS ~]$ id
uid=1003(user3) gid=1236(it) groups=1236(it),1003(user3) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
```

> [!tip] 
 组密码只对「非组成员」**生效；如果用户是该组成员，那么`newgrp`不要求输入密码。


> 实例：将user2中移出张三组
```bash
# 过滤张三组内的信息
[root@centos ~]# cat /etc/group |grep zhangsan
zhangsan:x:2001:user,user1,user2

[root@centos ~]# gpasswd -d user2 zhangsan
Removing user user2 from group zhangsan

[root@centos ~]# cat /etc/group |grep zhangsan
zhangsan:x:2001:user,user1
```




  
# 4.用户密码文件、哈希处理以及密码策略

## 用户密码文件

- 用户密码信息文件存放在**`/etc/shadow`**
```bash
# 该密码文件没有任何权限，即使是root用户也没有权限
[root@centos ~]# ll /etc/shadow
----------. 1 root root 1296 Feb 14 13:47 /etc/shadow
```

- 当一个用户登录系统时，系统会先检查`/etc/passwd`中是否有该用户，如果有，则去`/etc/shadow`中验证该用户的密码是否正确，如果正确，则用户登录成功

  
- 文件条目解释
```bash
[root@centos ~]# cat /etc/shadow | grep root

root:$6$nnleaIlijLfuQFKt$Yl/XtI6wj8045gvH5SQf7KLbWNXssmc0R9OisGdIsXGcUaGmAVMi46JRUFepNlFnUdb3KIksy3Wzd9WWp7Fs81:20268:0:99999:7:2:20269:
```
- 第一个栏位： 用户名
- 第二个栏位： 用哈希加密过的密码
- 第三个栏位： 密码最后变更的时间 20268 从1970年1月1日到密码更改的当天一共经历的天数
- 第四个栏位： 密码最小存活期。例如将0修改为2，管理员给用户设置的密码，2天后用户才可自行更改，如果是0，则表示用户可以随时更改自己的密码
- 第五个栏位：密码最大的存活期 99999 密码永不过期，如果修改为30，则表示30天必须改密码，否则不能登录
- 第六个栏位： 密码的警告天数，密码到期前7天会警告用户

  

  
## 哈希处理

>[!tip]
> 应用场景：防止文件传输过程中，遭到篡改，可以通过哈希值来进行比对确定
>- 例如某些Linux的ISO镜像文件，并不是从正规或者官方下载的，网站可能对ISO文件进行了修改，如果进行使用，会导致后期出现很多问题。如果需要确认ISO文件是否有问题，可以通过计算哈希值来进行比对 

- 哈希与加密
	- **加密(Encryption)**：是**双向**的，可以解密还原。只要通过对应的密码加密算法，就可以将密文进行解密得到明文密码
	- **哈希（Hashing）**：是**单向**的，理论上不可逆。没有解哈希的说法，明文通过哈希处理后，得到哈希值，这个过程是不可逆的。
```text
加密：
明文 → 加密 → 密文 → 解密 → 明文
          ↑
        可逆

哈希：
明文 → 哈希 → 哈希值
          ↑
        不可逆
```

>[!caution] 注意
>哈希的过程虽说是理论上不可逆，但是可以通过暴力破解或者字典破解的办法，通过不断比对哈希值，来实现对密码的破解
 
- 常见用途
	- **文件完整性校验**：通过比较文件的哈希值，判断文件内容是否发生变化。
	- **密码验证**：系统通常不会直接保存用户明文密码，而是保存经过密码哈希处理后的结果。

> [!tip]
> 下面介绍的这些哈希算法全部都不建议用来对密码进行哈希处理，目前对密码进行哈希处理的使用的是专用的哈希算法，例如Argon2、bcrypt、scrypt、PBKDF2


- MD5哈希算法是很弱的，目前MD5已经被破解攻破，不会再去使用该加密算法对密码进行加密或者检测文件完整性，该算法已经被彻底淘汰。

- 下面通过对同一个文件进行哈希处理，可以看到经过SHA-512哈希算法得到的的哈希值，是最长最复杂的
```bash
# MD5哈希算法
[root@CentOS opt]# md5sum test.txt
68b329da9893e34099c7d8ad5cb9c940  test.txt

# SHA-1哈希算法
[root@CentOS opt]# sha1sum test.txt
adc83b19e793491b1c6ea0fd8b46cd9f32e592fc  test.txt

# SHA-224哈希算法
[root@CentOS opt]# sha224sum test.txt
48837a787f07673545d9c610bcbcd8d46a2691a71966d856c197e69e  test.txt

# SHA-256哈希算法
[root@CentOS opt]# sha256sum test.txt
01ba4719c80b6fe911b091a7c05124b64eeece964e09c058ef8f9805daca546b  test.txt

# SHA-384哈希算法
[root@CentOS opt]# sha384sum test.txt
ec664e889ed6c1b2763cacf7899d95b7f347373eb982e523419feea3aa362d891b3bf025f292267a5854049091789c3e  test.txt

# SHA-512哈希算法
[root@CentOS opt]# sha512sum test.txt
be688838ca8686e5c90689bf2ab585cef1137c999b48c70b92f67a5c34dc15697b5d11c982ed6d71be1e1e7f7b4e0733884aa97c3f7a339a8ed03577cf74be09  test.txt
```

>[!tip]
>哈希算法越复杂，对文件或者密码处理的过程时间就越长


- 复制文件到另外一个目录下后，其文件的哈希值保持不变
```bash
# 复制文件到另外一个目录后，文件哈希值仍然保持不变，一般认为文件内容没有发生便阿虎
[root@CentOS opt]# cp test.txt /root
[root@CentOS opt]# cd /root
[root@CentOS ~]# sha256sum /root/test.txt
01ba4719c80b6fe911b091a7c05124b64eeece964e09c058ef8f9805daca546b  /root/test.txt
[root@CentOS ~]# sha256sum /opt/test.txt
01ba4719c80b6fe911b091a7c05124b64eeece964e09c058ef8f9805daca546b  /opt/test.txt

# 复制文件到另外一个目录并改名
[root@CentOS opt]# cp test.txt /root/hahahahah.txt
[root@CentOS opt]# sha256sum /opt/test.txt
01ba4719c80b6fe911b091a7c05124b64eeece964e09c058ef8f9805daca546b  /opt/test.txt
[root@CentOS opt]# sha256sum /root/hahahahah.txt
01ba4719c80b6fe911b091a7c05124b64eeece964e09c058ef8f9805daca546b  /root/hahahahah.txt
```



- 但是一旦对文件内容进行了修改，哈希值就会随之发生变化
```bash
[root@CentOS opt]# sha256sum test.txt
01ba4719c80b6fe911b091a7c05124b64eeece964e09c058ef8f9805daca546b  test.txt
[root@CentOS opt]# echo ahhahahahhahah > test.txt
[root@CentOS opt]# sha256sum test.txt
01b4f6757f8f5b71faeec76d47f98ab209ba22301b7ab7dee9b566bc37452377  test.txt
```


- 如果将篡改内容进行了删除，哈希值仍然和之前保持一样
```bash
# 修改为之前的内容，哈希值回到初始值
[root@CentOS opt]# sha256sum test.txt
01ba4719c80b6fe911b091a7c05124b64eeece964e09c058ef8f9805daca546b  test.txt
[root@CentOS opt]# echo  > test.txt
[root@CentOS opt]# sha256sum test.txt
01ba4719c80b6fe911b091a7c05124b64eeece964e09c058ef8f9805daca546b  test.txt
```

- Windows上面有一个用于计算Hash的校验工具，MyHash64，可以对ISO这类的文件进行计算比对真实值，看文件是否被修改过
  

  

## 密码策略

![[Pasted image 20260920110524.png]](assets/Pasted%20image%2020260920110524.png)

- 主要命令：`chage`
- `chage`主要用法如下
```bash
# 主要语法
chage [OPTIONS] <username>

# 分别修改用户密码的最短期限，最长期限，警告周期和失效期限
chage -m 0 -M 90 -W 7 -I 14 user3

# 强制要求用户在下一次登录时更新密码
chage -d 0 user3

# 显示用户密码的信息
chage -l user

Last password change                                    : never
Password expires                                        : never
Password inactive                                       : never
Account expires                                         : never
Minimum number of days between password change          : 0
Maximum number of days between password change          : 99999
Number of days of warning before password expires       : 7

# 用户将于2020-10-10到期（YYYY-MM-DD格式
chage -E 2020-10-10 user3

# 登录账号之后，系统强制要求你修改用户的密码
**`chage -d 0 username
```


- 系统密码相关提示
```bash
# 系统警告密码将在3天内过期
[userl@centos8~]$ su-user5

# 系统提示必须修改密码
[userl@centos8-]$ su-user5

```


# \#四个关键文件

- 用户信息文件：`/etc/passwd`
- 用户密码文件：`/etc/shadow`
- 用户组信息文件：`/etc/group`
- 用户组密码文件`/etc/gshadow`

>[!tip]
>在Linux系统中，可以将这些文件拷贝出来，以防止系统故障，所有用户信息清空。这些文件，再次放回到Linux系统中后，系统会进行识别，保持原有用户信息不变，这是**Windows无法做到的**
