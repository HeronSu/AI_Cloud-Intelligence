>[!tip]
>在Windows系统使用中，用户会有一种使用问题或者说需求，有时候文件太多，无法精确找到文件位置，但是记得文件大致的名字，这就需要一个查询工具来帮助用户来查找磁盘中的文件

- 下面介绍三种文件查找工具
	- `which`
	- `locate`
	- `find`

# 1. which

- 主要用于查找一个二进制可执行文件（命令）的绝对路径，主要格式如下
```bash
which <command>
```

- 例如查找`useradd`，`ls`命令对应的二进制可执行文件的位置
```bash
which useradd
```

```
/usr/sbin/useradd
```

```bash
which ls
```

```bash
alias ls='ls --color=auto'
        /usr/bin/ls
```


>[!important]
>查询命令的绝对路径是为了有些情况下，脚本不支持环境预设的PATH变量，导致无法找到命令，所以使用绝对路径来表示命令执行

# 2. locate

>[!important]
>如果通过数据库搜索，其实会比单纯的文件查找要快得多

- 查询特点
1. 基于db数据库文件进行搜索，**第一次执行会报错**
```bash
locate passwd
```

```bash

```

2. 需要用`updatedb`来手动更新数据库
```bash
updatedb
```

截取部分内容如下，发现不仅搜出来名为`passwd`的文件，还搜索出来包含`passwd`字段的文件
```bash

/usr/lib/firewalld/services/kpasswd.xml
/usr/lib64/samba/pdb/smbpasswd.so

/usr/share/bash-completion/completions/ldappasswd
```

>[!tip]
>`locate`根据关键字查询，这种查询方式称为模糊查询

- 如果临时创建一个文件，该命令无法及时查询到。**需要等到数据库进行更新或者自己手动更新`updatedb`**
- 同理，如果更新数据库后，删除刚才创建的临时文件，此时在对同一个关键词进行查找，仍然可以搜索到，仍然需要数据库更新才可以查找最新状态。

- 常用选项
	- `-i` ：不区分大小写
	- `-n number` ：列举前number个匹配到的对象

>[!important]
> - `locate`命令的一大优点就是搜索速度很快，由于是模糊搜索，对于文件体量很大的系统来说，会比常规查询速度要更快一点
> - 缺点就是`locate`因为是根据db数据库文件查询，所以无法实时查询文件



# 3. find

## 特点与语法格式

- 特点
	- 如果没有指定搜索的目录，默认搜索当前目录下的文件，**并且是遍历整个目录内容**，意思是会将该目录下的所有子目录也会进行搜索
	- find可以**实时查询**，并且可以**根据各种条件来进行查询**
	- find可以在这些查找到的文件基础之上进行二次操作

- 语法格式：后买你跟的参数基本上都是可选项
```bash
find [查询目录] [查询条件] [动作]
```


## 查找条件

**1. 根据文件名查询**

- 根据文件名查询
```bash
find <path> -name <file> 
```

- 案例：在`/etc/`目录下搜索名为`passwd`的文件
```bash
find /etc/ -name passwd
```

```bash
/etc/pam.d/passwd
/etc/passwd
```

- 根据文件名查询，不区分大小写
```bash
find <path> -iname <file>
```

```bash
find /root/ -iname passwd
```

```bash
echo "Hello world" > Passwd
[root@CentOS ~]# find /root/ -name passwd
[root@CentOS ~]# find /root/ -iname passwd
/root/Passwd
```

>[!tip]
>在查询过程中，支持使用 * , ? , [ ]，[^]等等各种通配符。对包含通配符的文件名使用引号引用，否则会报错

```bash
find /etc/ -name "*passwd*"
```

```bash
/etc/pam.d/passwd
/etc/security/opasswd
/etc/passwd
/etc/passwd-
```

**2. 指定搜索深度**

- 指定最小深度
```bash

```

- 指定最大深度
```bash
find  <path> -maxdepth <nummber> <file>
```

- 案例：在`/root`目录下搜索所有以`.txt`结尾的文件，搜索深度最小两层，最大四层

```bash
find /root -mindepth 2 -maxdepth 4 -name '*.txt'
```

**4. 根据文件大小查找**

- 补充一个命令
```bash
dd if=/dev/zero of=/data/test1 bs=1M count=10
```

```bash
10+0 records in
10+0 records out
10485760 bytes (10 MB, 10 MiB) copied, 0.00232892 s, 4.5 GB/s
```

```bash
ll -h /data/test1
-rw-r--r--. 1 root root 10M Nov  7 20:14 /data/test1
```

- 具体解释：最终结果是文件并没有任何内容，但是用0全部填充了一遍
	- `dd`：device-to-device，从设备到设备
	- `if`：input file，输入文件，`/dev/zero`是一个零字符设备
	- `of`：output file，输出文件
	- `bs`：block size，块大小，可以自己定义
	- `count`：块个数，可以自己定义

>[!important]
>这个其实是通过先写入内存，然后再写入到硬盘中，并不是直接写入到硬盘中的，这里显示的速度其实是写入内存的速度

- 如果要对裸盘测试，可以直接加上一个参数，直接写入硬盘中
```bash
dd if=/dev/zero of=/data/test2 bs=4k count=102400 oflag=direct
```

```bash
102400+0 records in
102400+0 records out
419430400 bytes (419 MB, 400 MiB) copied, 5.69047 s, 73.7 MB/s
```

```bash
ll -h /data/test2
-rw-r--r--. 1 root root 400M Nov  7 20:17 /data/test2
```

>[!tip]
>这个测试其实也不精准，因为对于磁盘来说，小IO是测试不出来磁盘型性能的


- **`-size +/- 文件大小`** （常用单位 k M G，分别对应KB，MB，GB）
```bash
[root@webserver data]# ll -h
total 430M
-rw-r--r--. 1 root root   10M May 31 14:26 test1
-rw-r--r--. 1 root root  400M May 31 14:29 test2
-rw-r--r--. 1 root root   15M May 31 14:39 test4
-rw-r--r--. 1 root root  5.0M May 31 14:39 test5
```

- 分别按照下面要求在`/data`目录下进行查询
	- 文件大小大于10M
	- 等于10M
	- 小于10M

```bash

/data/test4
[root@webserver ~]# find /data/ -size 10M

[root@webserver ~]# find /data/ -size -10M
/data/
```

**6. 根据权限查找**

- -perm [/ or -]MODE
    - MODE 精确匹配权限
    - /MODE 任何一类(u,g,o)对象的权限中只要能一位匹配即可，属于或关系。以前用'+',rhel 7以后'/'替代
    - -MODE 每一类对象都必须同时拥有指定权限，属于与关系
    - 0 只有**使用`/`或者`-`的时候才表示不关注**，如果是精确匹配中属于匹配没有权限的

- 示例
（1）严格匹配644的文件，也是属于精准搜索
```bash
find -perm 644
```


（2）u,g,o任何一类用户有写权限即匹配
```bash
find -perm /222 
```


（3）仅严格匹配写权限，即每个用户必须要有写权限
```bash
find -perm -222 
```


（4）表示仅严格匹配other用户的写权限
```bash
find -perm -002
```

**8. 根据时间戳查找**

* 搜索时间戳类型
	- `-atime [+-] 时间`：根据文件访问时间搜索
	- `-mtime [+-] 时间`：根据文件修改时间搜索
	- `-ctime [+-] 时间`**：根据文件改动时间搜索(属性)
- 时间表示
	- `[a/m/c]time`表示天数，**`[a/m/c]min`**表示时间

- 例子
	- +7 表示7天以及7天之前的时间
	- -7 表示7天之内的时间
	- 7 表示7-8天的时间（包含第7天）
    
- 案例：查找`/etc`目录下5天之内被修改的文件
```bash
find /etc -mtime -5 
```

## 执行动作

- **`-print`**: 默认动作，显示至屏幕
- **`-ls`**: 类似于对查找到的文件执行 ls -l 命令
- **`-delete`**: 删除查找到的文件
- **`-fls file`**: 查找到的所有长格式的信息保存至指定文件中
- **`-ok COMMMAND {} \;`** 对查找到的每个文件执行由COMMAND指定的命令，**且都会交互式要求用户确认**
>[!tip]
>针对删除这类危险操作，这类执行动作还是有是用的必要


- `-exec COMMAND {} \;` 对查找到的每个文件执行由COMMAND指定的命令；
    
>[!note]
>`{}`: 用于引用查找到的文件名称自身

- 案例：在`/etc`中查找以`.conf`结尾的文件，搜索最大深度为1，将搜索结果，复制到`/data/conf`目录下备份并保留权限
```bash
find /etc/ -maxdepth 1  -name '*.conf' -exec cp -a {}  /data/conf/ \;
```


- 由于很多命令不支持管道（|）来传递参数，而日常工作中有这个必要，所以就有了`xargs` 命令；相较于使用`exec`会相对来说方便一点，无非就是比日常使用管道符加了一个参数
```bash
find |xargs COMMAND
```

- 这是一个通过管道符的案例：在当前目录下查找所有以 `.sh` 结尾的脚本文件，并统一赋予它们 `755`（可执行）权限。
```bash
find -name "*.sh" | xargs chmod 755
```
