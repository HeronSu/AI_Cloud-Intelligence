
# 文件系统

## 文件系统概念

- 文件系统（File System）是操作系统用于**管理存储设备（如磁盘、SSD）上数据和元数据的一套机制与规则**。
- 本质是在底层物理块设备和上层应用之间建立一座“逻辑桥梁”

把文件放在某个文件夹（目录）下”，其实是一种**逻辑映射**。
1. 如果没有文件系统，硬盘只是一堆未格式化的物理扇区，无法直接存放文件。
2. 硬盘必须先创建文件系统，它会在物理存储之上建立一套规则（管理 inode、block等）。
3. 文件最终保存在文件系统里，由文件系统负责将逻辑上的“目录和文件”映射到物理上的“硬盘扇区”。没有文件系统，硬盘就只是一个无法读取的裸设备。

>[!tip]
>这一点在Windows有类似的体现：对于为通过文件系统格式化的磁盘，是无法被使用的


## 文件系统类型

1.本地文件系统：文件系统是在本机上的磁盘上创建的，**这个文件系统只能在本机进行使用**
- Windows的NTFS
- Linux的XFS ext系列：xfs，ext2/ext3/ext4
>[!note]
>主流的本地文件系统类型：ext4/xfs

2.网络文件系统：通过网络形式来存储文件到文件系统中，这类文件系统可以将文件通过网络共享
- NFS：Network FileSystem，网络文件系统，可以实现跨主机的文件共享
>[!note]
>Linux和Linux主机实现目录共享，比如Linux和Unix之间实现目录共享
- CIFS：实现文件共享：Linux和Windows主机实现目录共享，Linux主机默认不支持，必须要安装cifs-utils软件包才能支持CIFS

3.光盘文件系统：iso9660，这里的`/dev/sr0`为光盘

## 块设备

- 常见设备类型主要有以下几种类型

|     设备类型     | 设备名称                          |
| :----------: | :---------------------------- |
|     IDE      | `/dev/hda`, `/dev/hdb...`     |
| SATA/SAS/USB | `/dev/sda`, `/dev/sdb...`     |
|  NVMe（SSD）   | `/dev/nvme0`, `/dev/nvme1...` |
|  virtIO虚拟设备  | `/dev/vda`, `/dev/vdb...`     |
|    LVM逻辑卷    | `/dev/mapper/*`               |

- IDE设备：目前已经被淘汰了，几乎不会看到
- SATA/SCSI/U盘设备
	- 第一块SCSI设备：`/dev/sda`
	- 第二块SCSI设备：`/dev/sdb`
	- 第三块SCSI设备：`/dev/sdc`
>[!tip]
>一般块设备名是通过设备类型+数字或者字母顺序来进行命名的

- NVME设备：性能最好，价格较高
	- 第一块NVME：`/dev/nvme0n1`
	- 第二块NVME：`/dev/nvme0n2`

- LVM逻辑卷设备
	- `/dev/mapper/rhel-root`
	- `/dev/mapper/centos-root`
>[!note]
>`/dev/mapper`都是逻辑上的设备，简单来说就是虚拟出来的设备

- virtIO虚拟设备：虚拟机的磁盘设备，使用不同的虚拟化的虚拟机，对应的虚拟设备命名是存在差异的
	- KVM虚拟化的虚拟机
		- 第一块：`/dev/vda`
		- 第二块：`/dev/vdb`
	- XEN虚拟化的虚拟机
		- 第一块：`/dev/xvda`
		- 第二块：`/dev/xvdb`

# inode与block

## inode概念

- 文件系统创建之后，具备inode和block概念
- inode(Index Node)：索引节点，**用于存储文件元数据（除了文件名以外的所有属性）以及指向文件真实数据块指针的结构体**。每个文件都会被分配一个inode编号

- 查看inode编号的方式
```bash
ll -i /etc/passwd
```
最前面的数字就是inode编号
```bash
67981051 -rw-r--r--. 1 root root 2793 Nov 13 21:01 /etc/passwd
```


- inode存储的元数据信息包括
	- 文件类型，文件大小，时间戳
	- 文件链接数
	- 权限，UID，GID
	- 指针--->指向block的位置
	- 文件的其他信息
>[!note]
>简单来说，inode存储的文件元数据基本上就是`ls -l`命令所列出来的文件内容

```bash
[root@CentOS ~]# ll
total 17624
-rw-------. 1 root root     1257 Jan 24  2026 anaconda-ks.cfg
drwxr-xr-x. 2 root root        6 Jan 24  2026 Desktop
drwxr-xr-x. 2 root root        6 Jan 24  2026 Documents
drwxr-xr-x. 2 root root        6 Jan 24  2026 Downloads
-rw-r--r--. 1 root root     1549 Jan 24  2026 initial-setup-ks.cfg
```

- inode的数量是有限的，通过下面的命令来进行查看文件系统的inode数量，前提是该文件系统被挂载给了一个块设备
```bash
df -i
```
Inodes，IUsed，IFree分别显示Inode总数，已使用数量，剩余数量

>[!caution]
>一旦文件系统的inode数量分配完毕，则此文件系统无法再创建新的文件

- 如果出现文件创建不出来的情况，有一种可能就是inode没有剩余的了
```bash
[root@node1 ~]# touch /media/yutianedu
touch: cannot touch '/media/yutianedu': No space left on device
```

- 如果查看该文件系统的情况，显示仍有很大的可用空间




## block概念

- block：块，是文件系统读写数据的**最小逻辑的单位**，即是文件系统在底层存储真实数据（文件正文、目录内容）的固定大小的“集装箱”。
>[!important]
>inode存属性，block存内容

- block的大小在格式化的时候就已经确定，所以要调整只能在创建文件系统时指定block的大小，常见的默认大小是4KB（也可以设置为1KB、2KB、8KB 等）

>[!warning]
>block大小不能太大，也不能太小

- 例如一个3KB大小的文件，如果block大小为1KB，那么该文件就会有三个指针指向这三个block，会导致读取速度变慢，一次读取多次磁盘IO。如果block大小为4KB，只需要一个block，同时只有一个指针指向该block

## 文件与目录的底层组成

>[!tip]
>在前面我们了解了inode和block的基本概念
>- 文件系统的inode记录的是文件的元数据
>- 文件系统的block记录的是文件的数据
>那么对于普通文件和目录文件的底层是如何组成的呢

- 普通文件组成：元数据+数据
	- 普通文件元数据：保存的是文件权限、文件大小、文件时间戳、指针......
	- 普通文件数据：保存的是文件的内容


- 目录文件组成：元数据+数据
	- 目录文件元数据：保存的是文件权限、文件大小、文件时间戳、指针......
	- 目录文件数据：保存的是目录下文件名和inode映射关系

如果这么看目录的大小，实际上很小，但是这个显示出来的大小，实际存储的就是目录的文件数据，存放目录下文件名和inode的映射关系
```bash
ll -dh /etc/
drwxr-xr-x. 140 root root 8.0K Nov 17 20:57 /etc/
```

- 如果要看实际的目录大小，使用下面这条命令
```bash
du -sh /etc/
```

## 命令与inode关系

- 下面将介绍三个命令与inode的关系
	- `mv`与inode的关系
	- `cp`与inode的关系
	- `rm`与inode的关系

### mv
---

- 在同一个文件系统中使用`mv`移动文件，速度很快，即使是很大的文件移动也是如此，是因为移动过程中只会更改inode和文件名映射关系，底层的block位置是不会变化的，所以在同一个文件系统中mv或者剪切速度非常的快。

- 生成一个10G的文件，查看下移动前的inode编号
```bash
[root@CentOS ~]# dd if=/dev/zero of=test.txt bs=1G count=10
10+0 records in
10+0 records out
10737418240 bytes (11 GB, 10 GiB) copied, 9.89401 s, 1.1 GB/s
[root@CentOS ~]# ll -hi test.txt
100670075 -rw-r--r--. 1 root root 10G Nov 17 21:58 test.txt
```

- 移动该文件至`/opt`目录下，移动速度秒级，而且inode编号没有发生变化
```bash
[root@CentOS ~]# mv test.txt /opt/
[root@CentOS ~]# ll -hi /opt/
total 10G
100670075 -rw-r--r--. 1 root root 10G Nov 17 21:58 test.txt
```


- 在不同文件系统中使用`mv`移动，会在新的文件系统中开辟一个同等大小的存储空间来存储数据，然后这个新的文件系统会分配一个新的inode给文件，老的文件系统删除inode和文件名的映射关系

- 具体图示如下
![[mv_inode.svg|700]]



### cp
---

- `cp`命令命令会拷贝文件或者目录，拷贝之后，会在文件系统上分配一个和源文件同等大小的存储空间然后给新文件使用，并且文件系统也会分配一个新的`inode`给新文件使用

- 具体图示如下
![[cp_inode.svg|700]]




### rm
---

- rm删除文件，但**实际上rm删除的是文件名和inode的映射关系**
- 文件指向的block位置还是存在的，里面的数据依旧是在的，只不过这个block会变成可分配状态，如果下一个新的文件继承了这个inode，可能会因为新文件的数据写进来从而导致将原来的block数据进行覆盖

# 软链接与硬链接

## 软链接

- 软链接（Symbolic Link）：也被称为是符号链接，可以理解为是Windows中的快捷方式。一个文件指向另一个文件。**软链接可以跨文件系统**
- 创建软连接通过下面的命令即可，既可以为文件创建软链接，也可以为目录创建软链接
```bash
ln -s <source file or directory path> <link name>
```

```bash
ln -s /root/passwd passwd
```

```bash
[root@CentOS opt]# ll
total 0
lrwxrwxrwx. 1 root root 12 Nov 19 20:00 passwd -> /root/passwd
```

- 对于源文件和软链接来说，无论修改哪一个的内容，最终文件中的数据都是同步的，因为软链接本质上是一个保存了源文件路径的独立文件，系统访问软链接时会自动重定向到源文件，如果将文件删除了，那么软链接就会失效，也就变成了死链接。

>[!tip]
>主要应用场景：
>- 节省磁盘空间，对于某些项目需要指向同一个文件，那么只需要在项目目录中创建软链接指向该文件即可，多个项目就可以共享资源
>- 网站版本升级与切换：如果存在两个版本v1.0和v2.0两个文件夹，只需要创建一个软连接指向v1.0，后期升级时，只需删掉旧链接，重新指向一个指向v2.0的链接即可



## 硬链接

- 硬链接：可以理解为同一个 inode 在不同目录下新增一条目录条目，对于系统而言，由于硬链接文件和源文件inode编号是一致的，所以认为是同一个文件，因为数据底层是同一个
- 链接文件和源文件之间数据依旧是同步的

- 创建硬链接，执行下列命令
```bash
ln <source file or directory path> <link name>
```

```bash
ln /root/passwd passwd
```

可以看到硬链接创建出来，并不会有像软链接那样的箭头指向
```bash
[root@CentOS opt]# ll
total 4
-rw-r--r--. 2 root root 2589 Nov 19 19:59 passwd
```

- 硬链接文件，如果删除源文件，链接文件仍然可以访问到，因为两个文件（名）本质上共享了同一个 inode 编号。
![[Hard- Link.svg|700]]


>[!tip]
>硬链接是不能跨文件系统的，因为有一个前提条件是，硬链接文件和源文件的inode编号是一致的。而软链接是可以跨文件系统的，这就会导致链接文件和源文件的inode编号是不一致的
