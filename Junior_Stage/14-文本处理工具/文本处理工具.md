# 文本提取工具

- 文本提取工具：从文本中取出需要的内容
- 作用：按行、列、字段、模式，从大段文本中筛选或抽取指定部分，不改变原文件内容。


## 1.cat

> **连接（concatenate）文件并把内容输出到标准输出**

- 主要语法：对文件内容直接输出，输出到屏幕上的是所有内容
```bash
cat <filename>
```

> [!note]
> 下面对`cat`的常见使用进行介绍


1. 常用选项
- `-A` 显示特殊字符（**在window端复制到shell脚本中，可能会出现特殊字符**），下面从windows系统中拷贝文件至Linux系统，分别使用直接输出和加参数输出两种方式。
```bash
[root@CentOS ~]# cat test.txt
#!/bin/bash
for i in 1 2 3 4 5
do
  echo "输出第 $i 行"
done[root@CentOS ~]# cat -A test.txt

#!/bin/bash^M$
for i in 1 2 3 4 5^M$
do^M$
  echo "M-hM->M-^SM-eM-^GM-:M-gM-,M-, $i M-hM-!M-^L"^M$
done[root@CentOS ~]#
```

| 符号      | y&n真实存在于文件    | 是否影响脚本执行      | 说明                       |
| ------- | ------------- | ------------- | ------------------------ |
| `^M`    | 是（`\r`）       | **严重影响**      | CRLF 换行，最常见问题，必须处理       |
| `$`     | 否（显示标记）       | 本身不影响         | 但行尾空格在续行等场景可能影响          |
| `^I`    | 是（Tab）        | shell 脚本一般不影响 | Makefile 里 Tab 是语法要求     |
| `M-xxx` | 是（非 ASCII 字节） | 看位置           | 字符串/注释里多为乱码，语法位置会报错      |
| BOM     | 是（`EF BB BF`） | **会影响**       | 导致 `bad interpreter`，需去除 |

这种类型属于Shell脚本，修改文件后缀名以及文件权限后，尝试执行该脚本，发现无法执行，报错提示如下，显示存在所谓的回车符
```bash
mv test.txt test.sh
chmod a+x test.sh

[root@CentOS ~]# ll test.sh
-rwxr-xr-x. 1 root root 68 Oct 20 08:54 test.sh
[root@CentOS ~]# sh test.sh
test.sh: line 3: syntax error near unexpected token `$'do\r''
'est.sh: line 3: `do
```

>[!important]
> 根据上面的案例，建议是不要从windows系统上编辑文件然后上传至Linux，会自动产生很多的特殊字符，但是可以上传未经编辑的文件，或者在windows上编辑完成后，复制内容至Linux，这两种方式都比较建议

- `-n` 显示行号
```bash
 cat -n passwd
     1  root:x:0:0:root:/root:/bin/bash
     2  bin:x:1:1:bin:/bin:/sbin/nologin
     3  daemon:x:2:2:daemon:/sbin:/sbin/nologin
     4  adm:x:3:4:adm:/var/adm:/sbin/nologin
     5  lp:x:4:7:lp:/var/spool/lpd:/sbin/nologin
     6  sync:x:5:0:sync:/sbin:/bin/sync
     7  shutdown:x:6:0:shutdown:/sbin:/sbin/shutdown
```



**2. 文件整合：将多个文件内容整合为一个文件**

```bash
cat filename1 filename2 ... > filename
```


**3. 快速生成文件：用输出重定向和输入重定向**
```bash
cat > /opt/passwd <<aaa

huawei123
redhat
hello world
aaa

cat /opt/passwd

huawei123
redhat
hello world
```

> [!tip]
> 一次性输出所有内容，如果内容太多，无法查找对应的内容，当然如果要查找指定的内容，可以配合`grep`命令来进行使用

```bash
cat <filename> | grep <certain content>
```


## 2.more

- 用法：`more <filename>` **通过上下键来进行翻页**，主要实现一些较为基础的功能
- 特点：一页一页的查询，**查询效率比cat高，不会一上来就读取所有的文本内容**，当前只显示占满整个屏幕的一页内容。当文件的内容查看结束，则会自动退出more。
```bash
more /etc/services

mailq           174/tcp                         # MAILQ
mailq           174/udp                         # MAILQ
xdmcp           177/tcp                         # X Display Mgr. Control Proto
xdmcp           177/udp
nextstep        178/tcp         NeXTStep NextStep       # NeXTStep window
nextstep        178/udp         NeXTStep NextStep       # server
bgp             179/tcp                         # Border Gateway Proto.
bgp             179/udp
bgp             179/sctp
prospero        191/tcp                         # Cliff Neuman's Prospero
--More--(1%)
```

>[!tip]
>使用`more`命令查看的技巧
>- 使用回车，一行一行往后查看文件内容
>- 使用空格，一页一页往后查看文件内容

- **使用`more`命令时，有一下几点注意
	- 可以对文件指定内容进行查找，但是查找过程中**无法显示语法高亮，且只能向下查找，无法往回进行查找**
	- 中断查找时，可以使用`Ctrl + C`进行中断，或者直接按`q`进行退出
	- 按下`v`键可以进入`vim`编辑模式，编辑完成后，使用`:wq`或者`:q!`等和`vim`编辑器下一样的退出模式，**返回到 `more` 的浏览界面**，然后再进行退出，回到终端界面



## 3.less

- `less`命令在使用过程中，类似于`man`帮助中的分页查询，功能更加强大
 
>[!important]
>与`more`命令不同的是，查找指定内容时，会显示语法高亮，且支持往前和往后查找

- `/关键字` 从上往下过滤，按小写`n`跳转到下一个关键字，按大写`N`往上对关键字进行查找

- `less`命令使用注意
	- 中断查找时，可以使用`Ctrl + C`进行中断，或者直接按`q`进行退出
	- 按下`v`键可以进入`vim`编辑模式，编辑完成后，使用`:wq`或者`:q!`等和`vim`编辑器下一样的退出模式，**返回到 `less` 的浏览界面**，然后再进行退出，回到终端界面


## 4.nl

- `nl`：显示行号，number list
- 主要用法如下
```bash
nl <filename>
```

- 案例如下：显示某个文件的行号
```bash
[root@CentOS opt]# nl passwd
     1  root:x:0:0:root:/root:/bin/bash
     2  bin:x:1:1:bin:/bin:/sbin/nologin

     7  shutdown:x:6:0:shutdown:/sbin:/sbin/shutdown

```

## 7.grep

- 特点：根据**关键字过滤关键字**所在的行**的内容，所以只能打印出一整行。
- 主要用法
```bash
grep <certain content or word> <file>
```

- 例如在如下文件中，过滤出包含root的内容
```bash
grep root /opt/passwd

root:x:0:0:root:/root:/bin/bash
root:x:0:0:root:/root:/bin/bash
root:x:0:0:root:/root:/bin/bash
```

- 但是较多使用场景下，会搭配管道符来进行使用，会较为方便
```bash
cat /opt/passwd | grep root

root:x:0:0:root:/root:/bin/bash
root:x:0:0:root:/root:/bin/bash
root:x:0:0:root:/root:/bin/bash
```

- 被过滤出的内容关键字，会显示红色，这是因为在`alias`别名中定义了如下内容
```bash
[root@CentOS ~]# alias
alias cp='cp -i'
alias egrep='egrep --color=auto'
alias fgrep='fgrep --color=auto'
alias grep='grep --color=auto'
```


> [!tip]
> 注：可以在多个文件中过滤关键字


**2. 常用选项**

| 常用选项           | 描述                |
| -------------- | ----------------- |
| `-w`           | 根据单词过滤关键字所在的行     |
| `-i` (ignore)  | 忽略关键字的大小写         |
| `-v`(反向匹配)     | 不匹配关键字所在的行将其他的行输出 |
| `-q` (quite)   | 静默模式，不会输出任何信息     |
| `-Ax` (after)  | 过滤关键字所在行以及后面x行    |
| `-Bx` (before) | 过滤关键字所在行以及前面x行    |
| `-Cx`          | 过滤关键字所在行以及前后x行    |
| `-n`(number)   | 显示关键字所在的行号        |
| `-r`           | 递归搜索目录中的文件内容      |
| `-c` (count)   | 统计关键字出现的行数        |


-  `-w`(word)：根据单词过滤关键字所在的行

# 正则表达式

>[!important]
> **这里引入正则表达式是为了将前面所学到文本处理工具和表达式联合起来使用，可以更加精准的对内容进行过滤**

- 概念：通过不同的元字符来过滤内容

## 1.基本正则表达式

**（1）`^`：表示以....开头的**

```bash
grep student /etc/passwd
student:x:1000:1000:student:/home/student:/bin/bash

grep ^student /etc/passwd
student`****`:x:1000:1000:student:/home/student:/bin/bash
```



**（2）`$`：表示以....结尾的**

```bash
grep "/bin/bash$" /etc/passwd 

root:x:0:0:root:/root:/bin/bash
student:x:1000:1000:student:/home/student:/bin/bash
zhangsan:x:1001:1001::/home/zhangsan:`****`/bin/bash
```



**（3）`<`：在字的末尾进行匹配；`>`：在字的末尾进行匹配**

```bash
grep '\<root\>' /etc/passwd

root:x:0:0:root:root:/bin/bash
operator:x:11:0:operator:root:/sbin/nologin
```

- 这一条命令等价于
```bash
grep -w root /etc/passwd
```



**（4）`.`：对任何单个字符进行匹配**



**（5）`[abc]`匹配列表中任意单个字符**

- 常见的有以下使用
	- `[a-z]` 匹配所有的字母
	- `[123]` 匹配1或者2或者3
	- `[0-9]` 匹配所有的数字

- 这里是过滤对以r开头，四个字符组成的关键字
```bash
grep 'r[abco][abco]t' /etc/passwd

root:x:0:0:root:root:/bin/bash
operator:x:11:0:operator:root:/sbin/nologin
```


`[^a-z]` 除了列表中任意单个字符不匹配，其他的字符都匹配

**（6）`\` 去掉后面单个字符的特殊意义**

- 一般在过滤内容中存在特殊符号，会使用反斜杠来去掉特殊含义
```bash
grep '\.' /etc/passwd
```


> [!note]
> 这一部分内容，建议对经常使用的可以记一下，其余的能用上的时候，再去查询相关用法，没有必要硬用和硬记


## 2.扩展正则表达式

>[!tip]
> 区别：扩展正则表达式支持的元字符更多，并且也包含基本正则表达式，不**过需要通过****egrep命令或者grep -E****来支持扩展正则的元字符**

**1. 数量匹配符（量词）**

- 用于控制前面**单个字符**或**一个分组**出现的次数。

| 符号          | 含义说明                     | 示例        | 示例解释                             |
| ----------- | ------------------------ | --------- | -------------------------------- |
| **`?`**     | 匹配前面的字符 **0次 或 1次**      | `colou?r` | 匹配 `color` 或 `colour`（u可有可无）     |
| **`+`**     | 匹配前面的字符 **1次 或 多次**      | `ab+c`    | 匹配 `abc`、`abbc`、`abbbc` 等（b至少1个） |
| **`{n}`**   | 匹配前面的项**正好 n 次**         | `root{3}` | 匹配 `roott`（只对紧挨着的 t 重复3次）        |
| **`{n,m}`** | 匹配前面的项 **至少 n 次，最多 m 次** | `a{2,4}`  | 匹配 `aa`、`aaa`、`aaaa`             |
| **`{n,}`**  | 匹配前面的项 **至少 n 次**（无上限）   | `a{2,}`   | 匹配 `aa`、`aaa`、`aaaa` 等（2个及以上）    |
| **`{,m}`**  | 匹配前面的项 **最多 m 次**（下限为0）  | `a{,3}`   | 匹配 空、`a`、`aa`、`aaa`（视具体引擎而定）     |

**2. 逻辑与分组操作符**

- 用于组合多个条件或将多个字符作为一个整体处理。

| 符号          | 含义说明                           | 示例                                         | 示例解释                                 |
| ----------- | ------------------------------ | ------------------------------------------ | ------------------------------------ |
| **`a\|b`**  | **逻辑或**，匹配 `a` 或者匹配 `b`        | `grep -Ei 'error\|fail' /var/log/messages` | 找出日志中包含 `error` 或 `fail` 的行          |
| **`(exp)`** | **分组**，将括号内的内容作为**一个整体（单项）**处理 | `(root){3}`                                | 匹配 `rootrootroot`（将 root 作为一个整体匹配3次） |

- 这也是一种过滤IP地址的方法。
```bash
ifconfig ens160 | grep -E '([0-9]{1,3}\.){3}[0-9]{1,3}' -o | grep -Ev '^255|255$'
```

> [!important]
> 这种过滤方法太过于复杂，只是单纯为了演示正则表达式而去过滤内容，实际使用中很少见到这种使用情况，不建议这么去使用。

## 2.sed

- `sed`：stream edit，流编辑器

- 特点：`sed` 在处理文件时，会从文件流中逐行读取内容，将当前处理的一行放入缓冲区（模式空间），执行完指令后输出，然后清空缓冲区，继续读取下一行。

**1. 常用选项**

> [!important]
> **进行操作时加上单引号**

- 文件初始状态如下
```bash
cat test.txt

root
user
user1
user2
NO NO NO NO
YES YES YES YES
```

- `-i`：对源文件进行操作

> [!tip]
> 注：为了保证回车之后，误修改，所以可以先备份然后再修改，这里sed提供了选项 `-i.xxx`。备份后的文件名是`<source filename>.xxx`

- `-n`：关闭默认输出，通常与 `p` 配合，只输出指定的行。

> [!note]
> 解释：如果sed来打印关键字所在的行的话，默认会输出模式空间的内容看起来就比较繁琐，通过-n选项可以直接打印出匹配关键字所在的行

```bash
sed '/^root|^zhangsan/p' passwd -n
sed -r '/^root|^zhangsan/p' passwd -n

root:x:0:0:rootxxxroot:/root:/bin/bash
zhangsan:x:1001:1001::/opt/zhangsan:/bin/bash
zhangsan02:x:1006:1007::/home/zhangsan02:/bin/bash
zhangsan03:x:1007:1008::/home/zhangsan03:/bin/bash
```


**2. 地址定界：指定sed要处理的行，如果不指定地址定界，则默认处理所有的行**

（1）直接指定操作的行数

```bash
sed '48 d ' /opt/passwd
```

  
  （2）直接操作的行数范围
  
```bash
sed '1,10 d' /opt/passwd
```


 （3）通过`$`指定最后一行

```bash
sed '$ d' /opt/passwd
```

 
  （4）根据关键字进行过滤（和grep一样）

```bash
sed '/root/p' /etc/passwd -n

root:x:0:0:rootxxxroot:/root:/bin/bash
operator:x:11:0:operator:/root:/sbin/nologin
```


 **3. 常用操作**

|操作|作用|
|---|---|
|`p`|打印匹配的内容|
|`d`|删除匹配的行|
|`s`|替换文本|
|`a`|在指定行后追加内容|
|`i`|在指定行前插入内容|
|`c`|将匹配的行替换为指定内容|


**4. 常用示例**

- 打印`/etc/passwd`文件中所有以user开头的行，不输出模式空间的内容
```bash
sed '/^user/p' /etc/passwd -n

user:x:1000:1000:user:/home/user:/bin/bash
user1:x:1001:1001::/home/user1:/bin/bash
```


**替换内容** 
- 想要删除`/etc/passwd`文件中第一行所有的root关键字
```bash
sed '1s/root//g' /opt/passwd
```

>[!note]
> 具体解释：1表示处理第一行，s/root// 表示替换root关键字为空（删除关键字）g表示全局替换，默认只会替换第一个匹配到的关键字

- 还有其他常见示例如下
```bash
sed 's/root/huawei/g' file

# 忽略关键字的大小写来进行替换
sed 's|root|huawei123|ig' file
```

>[!tip]
> 中间的字符随便什么都可以，常见的用斜杠`/`，或者`|`

  
  
**另存为文件**

- 需求：将 `SELINUX` 配置项设置为 `disabled`，并备份原有文件
```bash
sed -i.bak 's/^SELINUX=.*/SELINUX=disabled/' /etc/selinux/config
```

- 具体解释
	- `^SELINUX=`：匹配以 `SELINUX=` 开头的行。
	- `.*`：匹配该行剩余的所有字符。
	- `-i.bak`：修改文件前保留一个 `.bak` 后缀的备份文件。


> [!important]
> 这个常在修改配置文件时会使用到，自动备份文件，虽然有备份的功能，**仍然建议在执行之前将原配置文件进行备份**
