# 12-重定向和管道符
# 1.重定向

- 重定向又被成为是IO重定向
>[!note]
>什么是IO


- I(Input)：输入，默认来自于键盘
	- Standard input ： 标准输入 STDIN
- O(Output)：输出，默认来自于终端，输出的结果可能有正确的，可能有错误的
	- Standard output : 标准输出 STDOUT

## 输出重定向

>[!note]
>将显示屏上的内容输出到文件中

- 常用的输出重定向：这一类的重定向，主要含义是覆盖文件内容
	- `> filename`：**正确输出重定向**
		- 将正确输出结果保存到文件中（**危险，覆盖）**，错误输出显示屏幕上
	- `2>filename`：**错误输出重定向**
		- 将错误的输出以覆盖的方式写到文件中，正确输出显示在屏幕上
	- `&>`：所有输出重定向
		- 正确和错误的输出重定向到文件中（覆盖），无输出显示在屏幕上

>下面对上述案例分别进行演示

**3.所有输出重定向**
- 将所有输出结果重定向到一个文件中，终端上并没有任何输出结果
```bash
[user@CentOS ~]$ find /etc/ -name passwd &> all.txt
[user@CentOS ~]$
```

- 查看文件内容，将原有所有输出全部重定向到文件中
```bash
[user@CentOS ~]$ cat all.txt
find: ‘/etc/pki/rsyslog’: Permission denied

find: ‘/etc/lvm/backup’: Permission denied
```

> [!tip]
**应用场景：测试网络连通性。当有很多个IP地址，测试当前主机是否和这些IP能够通信。如果通信不了的结点，将IP地址写入到文件中，后续方便去排查问题。**

- 还有一类情况如下，将空内容覆盖到整个文件。这种使用方法，还是有一定的使用场景的。对于系统中存在的一些日志文件，通常会记录系统的各种行为，久而久之，这些日志文件的内容会越来越多，所以需要定时进行清理，通常会利用计划任务来进行触发清理。
```bash
echo > log.txt
```


- 输出追加重定向
	- **`>> filename`**：将正确输出追加到文件的末尾处
	- **`&>>`** 正确和错误的输出重定向到文件中（追加）
	- **`2>>filename`** 将错误的输出以追加的方式写到文件中

>[!caution]
> 所谓追加是将内容追加到已经有内容的文件或者没有内容的文件
> - 切记，对于有内容的文件，如果想要追加内容的话，不要使用`>`重定向，对于标准重定向来说，**含义是覆盖文件内容**，一旦文件内容被覆盖将无法找回，非常危险



## 一个特殊设备

- `/dev/null`：一个空设备
	- **类似于windows的垃圾桶**，但是windows的垃圾桶还原，**如果写的内容进去，怎么都找不了，也被称为黑洞文件**。后续编写脚本的时候，如果要进行判断语句，这个设备经常使用到，将输入结果输入到这个设备中

- 还是看上面的案例，并做变形。将错误的输出结果输出到这个所谓的“黑洞文件”中
```bash
find /etc/ -name passwd 2> /dev/null

/etc/pam.d/passwd
/etc/passwd
```

>[!important]
> 对于`/dev/null`这个空设备来说，更多的是被使用到Shell脚本中，然后通过命令执行的返回值来判断命令是否执行成功



## 输入重定向

将键盘上输入的内容从文件中读取`<filename`
```bash
passwd user < passwd

Changing password for user user.
New password: BAD PASSWORD: The password is a palindrome
Retype new password: Password change has been aborted.
passwd: Authentication token manipulation error
```



这个报错的原因是因为，passwd文件中只有1行内容
```bash
passwd user < passwd

Changing password for user user.
New password: Password change has been aborted.
passwd: Authentication token manipulation error
```


这种情况，是因为passwd文件在root的家目录下，因为SELinux的存在，它不让你passwd命令从文件中读取内容（解决方法：setenforce 0）。

**这种设置密码的方案还是过于麻烦，因为需要提前创建一个密码文件**



## 快速生成内容文件

- 快速生成内容的核心在于使用输入重定向与输出重定向，主要语法格式如下
```bash
command1 > filename << 结束标记(tag)
> content1
> content2
> content3
> 标记（tag）
```

- 生成如下文件内容，这种方式快速生成文件内容
```bash
cat > dvd.repo <<AAA

> huawei123
> redhat456
> AAA

cat dvd.repo

huawei123
redhat456
```




# 2.管道符

## 管道符及案例介绍

- 管道符：`|`

- 主要使用方式：将管道符前面的命令执行结果作为后面命令的参数使用。例如下面的这种使用方法，将command1的正确执行结果作为command2的参数，依次传递，支持多重管道。
```bash
command1 | command2 | command3 …
```


- 将文件所有内容输出为大写字母，`tr`转换字符，下面命令的含义是将所有小写字母转换为大写字母
```bash
cat passwd | tr "a-z" "A-Z"

ROOT:X:0:0:ROOT:/ROOT:/BIN/BASH
BIN:X:1:1:BIN:/BIN:/SBIN/NOLOGIN
DAEMON:X:2:2:DAEMON:/SBIN:/SBIN/NOLOGIN
ADM:X:3:4:ADM:/VAR/ADM:/SBIN/NOLOGIN
LP:X:4:7:LP:/VAR/SPOOL/LPD:/SBIN/NOLOGIN
SYNC:X:5:0:SYNC:/SBIN:/BIN/SYNC
SHUTDOWN:X:6:0:SHUTDOWN:/SBIN:/SBIN/SHUTDOWN
HALT:X:7:0:HALT:/SBIN:/SBIN/HALT
MAIL:X:8:12:MAIL:/VAR/SPOOL/MAIL:/SBIN/NOLOGIN
[root@CentOS opt]# x:29:29:RPC Service User:/var/lib/nfs:/sbin/nologin
```


- 快速修改密码，通过`echo`命令和管道符，将输出结果作为`passwd`的执行参数，也被经常使用在Shell脚本中。这种使用方式被称为非交互界面
```bash
echo redhat | passwd --stdin user

Changing password for user user.
passwd: all authentication tokens updated successfully.
```

>[!tip]
>正常的`passwd`命令是需要用户通过键盘输入密码，这种属于交互界面


- 过滤字符串，也可多次对内容进行过过滤
```bash
ls /etc |grep shadow

gshadow
gshadow-
shadow
shadow-
```
  

- 统计 `/etc` 目录下有多少个文件和子目录（不包括隐藏文件）。引入命令`wc`，命令原本是用来统计文件的行数（`-l`）、字数（`-w`）、字节数（`-c`）
```bash
[root@CentOS ~]# ls /etc/ | wc -l
264
```

 
 - 有一个特殊的现象，下面进行呈现，这里呈现的结果显示，并没有将错误结果进行统计，而是对正确的结果进行统计。
```bash
[user@CentOS ~]$ find /etc/ -name passwd | wc -l
find: ‘/etc/pki/rsyslog’: Permission denied
find: ‘/etc/lvm/archive’: Permission denied
find: ‘/etc/lvm/backup’: Permission denied
find: ‘/etc/lvm/cache’: Permission denied
find: ‘/etc/sssd’: Permission denied
find: ‘/etc/dhcp’: Permission denied
find: ‘/etc/grub.d’: Permission denied
find: ‘/etc/polkit-1/rules.d’: Permission denied
find: ‘/etc/polkit-1/localauthority’: Permission denied
find: ‘/etc/nftables’: Permission denied
find: ‘/etc/audit’: Permission denied

```

>[!warning]
>注：只能传输正确的结果，错误的无法经过管道符

- 所以这里使用一个重定向`2>&1`，将错误的结果当作正确的输出，并统计结果
```bash
[user@CentOS ~]$ find /etc/ -name passwd 2>&1 | wc -l
17
```



## 三通管道

- 三通管道的核心命令是`tee`
- `tee`命令：可以同时实现将结果输出到屏幕以及保存到文件，**故障诊断复杂的管道，同时查看和记载输出**，主要命令格式如下
```bash
commmand1 | tee filename |command2
```

> [!tip]
> 可以这么理解，`tee`命令让`command1`的结果输出，并同时这些输出结果也被保存到了指定的文件中去，这对于后续查看诊断复杂管道有非常重要的作用

- 需求：将系统中所有除root以外的用户，导出到`/root/userlist.txt`中，仅需要用户名列表
```bash
cat /etc/passwd |grep -v  root |grep /bin/bash |cut -d: -f1  > /root/userlist.txt
```
