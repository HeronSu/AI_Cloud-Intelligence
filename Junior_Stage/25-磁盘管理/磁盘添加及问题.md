# 相关问题
## 问题分析

- 对于虚拟机安装时使用的磁盘类型，那么上面添加磁盘时会有不同的处理
- 对于上面的有两种情况
	- 添加磁盘类型与安装系统的磁盘类型一致，那么就不会有任何问题。例如安装时NVMe，添加也是NVMe，安装时SCSI，添加也是SCSI，不会有任何问题
	- 添加磁盘类型与安装系统的磁盘类型不一致。例如上面的这种情况，安装时NVMe，添加磁盘是SCSI，那么就会出现问题，进入下面这种系统安装界面。

![[Pasted image 20261121210711.png|652]](assets/Pasted%20image%2020261121210711.png)

- 内核启动时，会先初始化SCSI子系统，后初始化NVMe子系统，所以会线识别到SCSI这块磁盘，但是新添加的这块磁盘上没有安装操作系统，导致系统找不到系统盘而启动失败，因为启动失败了，加上光驱还连着，BIOS 就自动顺着启动顺序回退到了光驱，从而把你带进了系统安装界面。

## 解决办法

- 右键虚拟机，点击电源-----打开电源时进入固件

![[Pasted image 20261121211725.png|577]](assets/Pasted%20image%2020261121211725.png)


- 通过左右方向键，移动到Boot，再通过上下方向键，选择到Hard Drive（硬盘），按Enter回车

![[Pasted image 20261121211934.png|632]](assets/Pasted%20image%2020261121211934.png)

![[Pasted image 20261121212036.png|635]](assets/Pasted%20image%2020261121212036.png)

- 上下键选中NVMe这块磁盘，按下`+`键，调整其优先级高于刚才添加的这块SCSI磁盘
![[Pasted image 20261121212105.png|646]](assets/Pasted%20image%2020261121212105.png)

- 按F10保存，这里选择Yes，回车退出

![[Pasted image 20261121212157.png|648]](assets/Pasted%20image%2020261121212157.png)

- 正常进入系统启动，正确识别到NVMe系统盘，问题解决！

![[Pasted image 20261121212251.png|649]](assets/Pasted%20image%2020261121212251.png)

- 进入系统查看磁盘是否被识别到，可以看到有一个单独的sda磁盘
```bash
[root@CentOS ~]# lsblk
NAME        MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
sda           8:0    0   20G  0 disk
sr0          11:0    1  9.3G  0 rom
nvme0n1     259:0    0  100G  0 disk
├─nvme0n1p1 259:1    0    1G  0 part /boot
└─nvme0n1p2 259:2    0   99G  0 part
  ├─cl-root 253:0    0 63.9G  0 lvm  /
  ├─cl-swap 253:1    0    4G  0 lvm  [SWAP]
  └─cl-home 253:2    0 31.2G  0 lvm  /home
```
