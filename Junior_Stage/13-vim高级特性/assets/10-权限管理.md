# 1.三类用户访问

- 访问文件或者目录的有三类用户
	- 文件拥有人（**user**）`u`
	- 文件拥有组（**group**）`g`
	- 其他人（**other**）`o`


# 2.文件权限

- 这里以`/etc/passwd`的线管权限
```bash
[root@centos ~]# ll /etc/passwd`**
-rw-r--r--. 1 root root 2626 Feb 14 13:47 /etc/passwd
```


- 第一个栏位：文件类型
    - **`-`**：普通文件
    - **`d`** 目录/文件夹
    - **`l`**: link 链接文件
    - **`b`**：block设备，也称块设备
    - **`c`**：字符型设备

```bash
# 目录
drwxr-xr-x. 2 root root    6 Jan 24  2026 Desktop

# 链接文件
lrwxrwxrwx. 1 root root      17 Jan 29  2021 xtables-monitor -> xtables-nft-multi

# 块设备
brw-rw----. 1 root disk    259,   0 Sep 21 09:58 nvme0n1  # 这是磁盘
brw-rw----+ 1 root cdrom    11,   0 Sep 21 09:58 sr0   # 这是ISO镜像

# 字符型设备
crw-------. 1 root root      5,   1 Sep 21 09:58 console
```


- **第二部分均为权限位**，每三个栏位为一组：
    - 第一组：拥有人权限，`rw`权限
    - 第二组：拥有组权限，`r`权限
    - 第三组：其他人权限，没有任何权限
- 对应数字1表示link count： 硬链接数
	- 对于目录来说，就是该目录下有几个子目录
	- 对于文件来说，数字一般是`1`
```bash
# 例如/home这个目录
drwxr-xr-x.   3 root root   18 Sep 21 19:47 home

# 这里显示只有一个目录
[root@CentOS ~]# ll /home/
total 0
drwx------. 4 user user 113 Sep 19 15:08 user

# 该目录下还有两个隐藏目录
[root@CentOS ~]# ls -a /home/
.  ..  user
```


- 剩余部分，分别对应拥有人，拥有组，文件大小，文件最后一次修改的时间（ Modify Time）以及文件名或者目录名
```bash
[root@CentOS ~]# ll -h /etc/passwd
-rw-r--r--. 1 root root 2.5K Sep 21 19:47 /etc/passwd
```




# 3.权限的具体解释


## 权限对文件的影响

- `r`(**read**)：可以读取文件的内容
- `w`(**write**)：可以更改文件的内容
- `x`(**execute**)：可以作为命令执行文件
	- 对于普通文件来说，拥有执行权限没有任何意义
	- 但对于可执行的脚本Shell就有存在的必要

> [!tip]
> 对于文件只有`w`，没有`r`权限的这种情况，有几种理解
> - 对于个人使用的一些普通文件来说，其实本质上没有什么意义，如果该文件被长期不断查看，那么对于用户个人来说，会比较麻烦
> - 但是并不是没有使用场景，其核心价值在于**“盲写（Write-only）”**。企业服务器上的某些敏感日志文件（例如审计日志、安全监控日志），往往只授予应用程序 **写权限**，不授予读权限。**目的**就是防止被攻破的服务进程或者恶意程序读取日志，从而了解监控系统的运作方式，进而规避检测。



## 权限对目录的影响

- **`r`**：可以查看目录中的内容
- **`w`**：可以创建或删除目录中的任一文件，同时也可以修改任一文件，并进行强制保存
- **`x`**：可以进入目录
> [!important]
> - 是否可以删除目录下的文件，不是看文件的拥有人和拥有组，也不是看文件的权限，而是看这个文件所在的目录是否有w权限，**有w权限，只要是这个目录下的文件，无论是谁创建的，都可以删除。**
> - 是否删除文件，看得只是该文件所在的目录，与目录的上一级目录无关 
> - 删除一个空目录，不需要看目录的**`w`**权限，但是删除一个非空目录，需要看目录的**`w`**权限


一个目录要想有意义，必须要有`r`和`x`的权限
- 如果只有`r`权限，但是由于没有`x`权限，依然无法查看目录的内容
- 如果只有`x`权限，但是由于没有**`r`**权限，即使可以进入目录，仍然无法查看目录内容

  

# 4.修改拥有人，拥有组，权限
---
## chown
---
> chown：change owner

- `chown`：修改文件或者目录得拥有人或者拥有组
- 修改目录/文件的拥有人
```bash
[root@centos opt]# ll -d libvirt/

drwxr-xr-x. 2 root root 6 Feb 14 18:34 libvirt/

[root@centos opt]# chown user libvirt/

[root@centos opt]# ll -d libvirt/
drwxr-xr-x. 2 user root 6 Feb 14 18:34 libvirt/
```



- 修改目录权限的同时，对目录内的所有文件修改为相同的拥有人
```bash
[root@centos opt]# chown -R user libvirt/
[root@centos opt]# ll -d libvirt/
drwxr-xr-x. 2`** **`user`** **`root 137 Feb 14 18:35 libvirt/
```


- 同时修改拥有人和拥有组，使用`:`或者`.`进行隔开
```bash
# 同时修改拥有人和拥有组，使用 : 隔开
[root@CentOS opt]# ll
-rw-r--r--. 1 root root 2548 Sep 21 20:42 passwd
[root@CentOS opt]# chown user:user passwd
[root@CentOS opt]# ll
-rw-r--r--. 1 user user 2548 Sep 21 20:42 passwd

# 同时修改拥有人和拥有组，使用 . 隔开
[root@CentOS opt]# chown root.root passwd
[root@CentOS opt]# ll passwd
-rw-r--r--. 1 root root 2548 Sep 21 20:42 passwd
```

  

## chgrp

> chgrp：change group

- 修改文件的拥有组
```bash
[root@centos opt]# chgrp zhangsan file123
[root@centos opt]# ll file123
-rw-r--r--. 1 root zhangsan 0 Feb 14 18:39 file123
```



- 修改目录拥有组的同时，修改目录下的所有文件的拥有组
```bash
chgrp -R user libvirt/
```




## chmod

- 字符方式修改
	- `+`代表增加权限
	- `-`代表去掉权限
	- 多个权限修改之间用`,`进行隔开，设置权限自行进行选择
```bash
[root@servera etc]# chmod o+w /opt/
[root@servera etc]# ll -d /opt
drwxr-xrwx. 2 root root 28 Jul 15 15:21 /opt

[root@servera etc]# chmod u-x,g+w,o=wx /opt

[root@servera etc]# ll -d /opt
drw-rwx-wx. 2 root root 28 Jul 15 15:21 /opt

[root@servera etc]# chmod u+x,g-w,o=rwx /opt

[root@servera etc]# ll -d /opt
drwxr-xrwx. 2 root root 28 Jul 15 15:21 /opt
```


> [!caution]
>注：不建议使用“=”，会发生权限覆盖，对于实际工作中（针对该情况o=r不太建议）


- 数字方式修改
    - **`r`**：4，拥有人权限
    - **`w`**：2，拥有组权限
    - **`x`**：1，其他人权限

```bash
[root@centos opt]# chmod 777 libvirt/

[root@centos opt]# ll -d libvirt/
drwxrwxrwx. 2 user zhangsan 137 Feb 14 18:35 libvirt/

[root@centos opt]# chmod 644 libvirt/

[root@centos opt]# ll -d libvirt/
drw-r--r--. 2 user zhangsan 137 Feb 14 18:35 libvirt/
```
