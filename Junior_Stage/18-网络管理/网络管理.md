
# 1.网络状态查询命令

> [!tip]
> `ifconfig`、`ip`、`nmtui`、`nmcli` 本质的方法直接看配置文件

## 查看网络信息

**1. `ifconfig`**

- 网络信息包括：IP地址、DNS地址、网关地址、子网掩码、广播地址等等等
- 核心命令：`ifconfig`
```bash
ifconfig
```

>[!note]
>类似的在Windows系统下，Powershell或者cmd中查看网络的命令`ipconfig`

- 如果想看到指定网卡的信息，在命令后接上网卡名即可
```bash
ifconfig ens160
```


- 输入内容如下，下面做基本解释
```bash
ens160: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 192.168.120.45  netmask 255.255.255.0  broadcast 192.168.120.255
        inet6 fe80::1aed:6d5b:e026:a5a7  prefixlen 64  scopeid 0x20<link>
        ether 00:0c:29:93:ef:19  txqueuelen 1000  (Ethernet)
        RX packets 1019  bytes 131001 (127.9 KiB)
        RX errors 0  dropped 0  overruns 0  frame 0
        TX packets 338  bytes 63527 (62.0 KiB)
        TX errors 0  dropped 0 overruns 0  carrier 0  collisions 0
```

- `<UP,BROADCAST,RUNNING,MULTICAST>`：显示网卡状态，依次表示网卡已开启，支持广播，正在运行，支持多播
- `mtu 1500`：最大传输单元，即网卡可以传输的数据包个数
- 第三行：依次表示IPv4地址，子网掩码，广播地址
- 第四行：IPv6地址
- 第五行：MAC地址，每一个网卡都有一个唯一的MAC地址，对于物理网卡是被烧录到芯片中的
	- `txqueuelen 1000 (Ethernet)` 网卡速率以及以太网类型的网络接口

>[!important]
>如果系统是Mininal最小化安装，不会自带`ifconfig`命令，需要安装软件包`net-tools`

## 查看路由

>[!tip]
>上面的`route -n`也是一种可以查看路由ixn*
- 查看路由表信息
```bash
ip route 
```

- 路由信息做一个基本解释 
	- `via 192.168.158.2` 表示通过该网关
	- `metric`表示优先级， **数字越小，优先级越高**
```bash
default via 192.168.120.2 dev ens160 proto static metric 100
192.168.120.0/24 dev ens160 proto kernel scope link src 192.168.120.45 metric 100
192.168.122.0/24 dev virbr0 proto kernel scope link src 192.168.122.1 linkdown
```

>[!important]
>为什么要提到这个案例？
>- 因为同一个操作系统上不可以存在多个默认路由，多个默认路由会导致网络存在问题，无法访问Internet，一般出现在修改网关的情况下。

- 案例：虚拟机无法访问Internet
查看路由信息如下，发现存在两条默认路由，且有一条路由优先级要更高
```bash
Kernel IP routing table
Destination     Gateway         Genmask         Flags Metric Ref    Use Iface
0.0.0.0         192.168.120.254 0.0.0.0         UG    50     0        0 ens160
0.0.0.0         192.168.120.2   0.0.0.0         UG    100    0        0 ens160
192.168.120.0   0.0.0.0         255.255.255.0   U     100    0        0 ens160
192.168.122.0   0.0.0.0         255.255.255.0   U     0      0        0 virbr0
```

- 删除与配置信息不一致的那条路由
```bash
ip route del default via 192.168.120.254 dev ens160 metric 50
```

- 再在配置文件中，删除对应网卡多余的网关信息然后重启NetworkManager服务
```bash
systemctl restart NetworkManager
```

>[!tip]
>这里如果发现了多条默认路由，更加直接的处理办法是**直接到配置文件中删除多余的网关信息**

# 2.网络服务与网卡配置文件

## 网络服务

>[!tip]
> 下面提到的版本是针对红帽系Linux

- 在9之前的版本，都是存放到`/etc/sysconfig/network-scripts/`
- 从9版本开始，网卡的配置文件存放到`/etc/NetworkManager/system-connections/`

>[!important]
> 注意：
> - 在9之前的版本使用的网络服务是network
> - 从9版本开始，使用的是NetworkManager服务，并且在9版本中，已经在软件包仓库里面将network对应的软件包给删除掉了


- 在9之前的版本中，有网络服务network，在`/etc/sysconfig/network-scripts/`又很多配置文件、控制脚本和公共函数库。
```bash
cd /etc/sysconfig/network-scripts/

ifcfg-ens33 ifdown-ppp ifup-ib ifup-Team
ifcfg-lo ifdown-routes ifup-ippp ifup-TeamPort
ifdown ifdown-sit ifup-ipv6 ifup-tunnel
ifdown-bnep ifdown-Team ifup-isdn ifup-wireless
ifdown-eth ifdown-TeamPort ifup-plip init.ipv6-global
ifdown-ib ifdown-tunnel ifup-plusb network-functions
ifdown-ippp ifup ifup-post network-functions-ipv6
ifdown-ipv6 ifup-aliases ifup-ppp
ifdown-isdn ifup-bnep ifup-routes
ifdown-post ifup-eth ifup-sit
```

- 从9版本开始，只有NetworkManager服务，没有network服务了，再去看`/etc/sysconfig/network-scripts/`目录下没有配置文件的内容，只有一个文件
```bash
cd /etc/sysconfig/network-scripts/

readme-ifcfg-rh.txt
```

部分信息展示，NetworkManager 会将新的网络配置文件以 keyfile（键值对）格式，存储到 `/etc/NetworkManager/system-connections/` 目录中。
```bash
NetworkManager stores new network profiles in keyfile format in the
/etc/NetworkManager/system-connections/ directory.
```


- NetworkManager网络服务的配置文件路径为`/etc/NetworkManager/system-connections/`，`connection`指网卡对应的连接，网卡配置文件实际上就是以`.nmconnection`为尾缀的文件。
```bash
cd /etc/NetworkManager/system-connections/
[root@controller system-connections]# ls
ens160.nmconnection
```

>[!caution]
>两个网络服务，尽量使用其中一个，不要两个都同时开启，因为在一些场景中会导致网络冲突。比如openstack开源云平台的部署，网络服务用的是network，把networkmanager服务也开启了，最后会导致每次节点开机的时候都无法获取到正确的IP地址。


## 网卡配置文件

>[!tip]
> 给网卡修改网络信息实际上是修改的网卡绑定的配置文件

- network服务对应的网卡配置文件，文件名通常以`ifcfg`为前缀，网卡名为后缀
```bash
ifcfg-xxx
```

- 该网卡配置文件内容如下
```bash
TYPE=Ethernet
PROXY_METHOD=none
BROWSER_ONLY=no
BOOTPROTO=none   
DEFROUTE=yes
IPV4_FAILURE_FATAL=no
IPV6INIT=yes
IPV6_AUTOCONF=yes
IPV6_DEFROUTE=yes
IPV6_FAILURE_FATAL=no
IPV6_ADDR_GEN_MODE=stable-privacy
NAME=ens160
UUID=b903f092-f48e-4916-ba8a-5be750c9b1a7
DEVICE=ens160
ONBOOT=yes
IPADDR=192.168.120.45
PREFIX=24
GATEWAY=192.168.120.2
DNS1=114.114.114.114
```

- 其实核心有用的部分只有下面这些内容，下面对核心部分做具体解释
```bash
TYPE=Ethernet    # 接口类型为以太网
BOOTPROTO=none   # 获取ip地址的方式，dhcp 通过dhcp获取，none/static 手动分配
NAME=ens160      # 这是连接名称，并不是网卡的名称，但是一般与设备名保持一致
UUID=b903f092-f48e-4916-ba8a-5be750c9b1a7
DEVICE=ens160    # 网卡名称，也是设备名称
ONBOOT=yes    # 是否开机自启，yes为开机自启，反之为no
IPADDR=192.168.120.45   # IPv4地址
PREFIX=24    # 子网掩码
GATEWAY=192.168.120.2   # 网关
DNS1=114.114.114.114    # DNS，可以有多个DNS地址，DNS1,DNS2
```

---
- NetworkManager对应的网卡配置文件，典型的INI格式
```bash
[connection]
id=ens160   # 连接名称（用 nmcli connection show看到的名字）
uuid=0a9d993c-2fbc-4512-9bc2-fd9af85e4a26  # 全局唯一标识符，系统识别这个连接，别乱改
type=ethernet   # 以太网类型
interface-name=ens160   # 绑定的物理/虚拟网卡设备名

[ethernet] # 以太网底层配置，为空表示默认配置

[ipv4]
address1=192.168.120.60/24,192.168.120.2   # 包含IP地址，子网掩码，网关信息
dns=114.114.114.114;     # DNS
method=manual    # 获取ip地址的方式，auto表示自动（与老格式中DHCP一致），manual手动

[ipv6]  # IPv6 配置
addr-gen-mode=default
method=auto

[proxy]  # 代理设置，服务器环境通常为空。
```

- 核心的配置只有下面几行
```bash
[connection]
id=ens160
uuid=0a9d993c-2fbc-4512-9bc2-fd9af85e4a26
type=ethernet
interface-name=ens160

[ipv4]
method=manual
address1=192.168.120.60/24,192.168.120.2
dns=114.114.114.114;
```


- 更改相关网络设置
>[!note]
> 案例1：为eth0新增一个配置文件，eth0网卡的ip地址为手动分配，ipv4地址192.168.2.110，24位子网掩码，DNS地址192.168.2.2，网关192.168.2.2，并且实现开机自启动

- 从这个案例开始，全部使用`nmcli`命令来进行配置
```bash
nmcli connection add type ethernet ifname eth0 con-name con-eth0 ipv4.method manual ipv4.addresses 192.168.2.110/24 ipv4.dns 192.168.2.2 ipv4.gateway 192.168.2.2 autoconnect yes
```


- 具体参数解释
	- `add`：添加
	- `type ethernet`：类型为以太网类型
	- `ifname eth0` ：网卡设备名，这个connection和哪个网卡绑定
	- `con-name con-eth0` ：connection的名字（网卡配置文件的名字）
	- `ipv4.method manual/auto` ：获取ipv4地址方式，手动/自动
	- `ipv4.addresses`： ipv4地址
	- `ipv4.dns`： DNS地址
	- `ipv4.gateway`：网关地址
	- `autoconnect yes`：开机自启动，默认不写这条也是开机自启动

- 如果要使得配置生效，还需执行下面的命令
```bash
nmcli connection down con-eth0 ; nmcli connection up con-eth0
```

- 也可以直接执行`up`命令，就可以直接生效
```bash
nmcli connection up con-eth0
```

```bash
nmcli connection modify con-eth0 ipv4.addresses 192.168.2.150/24`
```

# 4.本地host表

- 关键文件：`/etc/hosts`
```bash
127.0.0.1   localhost localhost.localdomain localhost4 localhost4.localdomain4
::1         localhost localhost.localdomain localhost6 localhost6.localdomain6
192.168.120.61 node1
192.168.120.62 node2
```

```bash
<Host IP Address> 别名 别名1 别名2 别名3   ---->这些别名都会解析到IP地址
```

>Windows的本地解析`C:\Windows\System32\drivers\etc\hosts`



# 5.标准服务开放端口

- 每一个服务启动都会监听一个端口
	- 在同一台服务器上，不同的服务会监听不同的端口。**这样做的目的是为了区分同一台主机上的不同应用程序。**
	- 通过不同的端口来进行访问，IP+Port访问方式,，IP目的是为了找到服务所在的主机，Port是为了区别不同的服务

- 系统服务端口目录：`/etc/services` 只是记录常见端口

- 查看当前网络监听端口状态
	- 主要有两个命令：**`netstat`和`ss`**
  
- `netstat`常用命令参数
```bash
netstat -tnulp
```

- 参数具体解释
	- `-t`：TCP端口，IPv4地址
	- `-u`：UDP端口，IPv6地址
	- `-p`：查看进程名和ID
	- `-n`：列出端口号
	- `-l`：查看监听窗台

- 输出结果如下
![[Pasted image 20261101215423.png|674]]

- `ss`与`netstat`使用上没有太大的差异

>[!important]
> - 对于使用上来说，`ss`和`netstat`没有任何区别，用户习惯哪个就使用哪个，作用都是一样的，都是查看服务的监听端口的状态以及对应的进程
> - 但是对于工作效率来说，更加推荐使用`ss`命令，对于大规模的监听下，`ss`的工作效率远远比`netstat`要高，`ss`直接看汇总的状态，`netstat`遍历查询
