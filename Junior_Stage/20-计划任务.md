# 计划任务

- 所谓计划任务**是一种用于定时或按条件自动执行后台任务**的机制
- 主流的计划任务有以下两种
	- 一次性计划任务
	- 周期性计划任务

## 1.一次性计划任务

### 基本使用

- 关键命令：`at`，交互式的方式创建一次性计划任务的命令工具
- 创建的主要格式
```bash
at 时间格式
```


- 时间格式的表现方式有很多，主要有以下几种

| 时间格式    | 案例               |
| ------- | ---------------- |
| 未来具体的时间 | 18:00 2025-12-12 |
|         | 18:00            |
| 抽象模糊的时间 | 8:05am           |
|         | 4pm + 3 days     |

- 创建at计划任务的步骤
	- at 时间格式
	- `Ctrl+d` 保存并且退出

- 引例：当输入某个时刻时，下方会出现`at>`命令行，输入要执行的任务。最后保存得到的结果是`job 1`表示是第一个任务
```bash
[root@CentOS ~]# at 19:08
warning: commands will be executed using /bin/sh
at> touch /opt/test.txt
at> echo "hello world" >> /opt/test.txt
at> <EOT>
job 1 at Thu Nov  5 19:08:00 2026
```

结果如下
```bash
cat /opt/test.txt
hello world
```

>[!important]
>- 如果指定的时间在当前系统时间之前，例如系统时间为`18:40`，但是任务时间为`17:50`，那么系统会认为在下一个时间来执行该任务，即第二天的该时间执行任务。
>- 但是注意，如果指定的时间精确到了年月日时分秒，那么此时执行命令就会报错，因为已经超过了当前的系统时间，无法再次指定任务


- **`at -l`** 列出当前的一次性计划任务，分别显示任务号，执行时间，任务名称，以及创建用户
```bash
at -l

2 Fri Dec 12 18:00:00 2025 a root
```


- `at -c <任务编号>` 查看计划任务的执行命令，展示部分内容
```bash
#!/bin/sh
# atrun uid=0 gid=0
# mail root 0
umask 22
...
SELINUX_USE_CURRENT_RANGE=; export SELINUX_USE_CURRENT_RANGE
SHLVL=1; export SHLVL
GDK_BACKEND=x11; export GDK_BACKEND
LOGNAME=root; export LOGNAME
DBUS_SESSION_BUS_ADDRESS=unix:abstract=/tmp/dbus-bkNNl1TPxI,guid=2b8666f9eea364ec8d43ce8e6aec616b; export DBUS_SESSION_BUS_ADDRESS
XDG_RUNTIME_DIR=/run/user/0; export XDG_RUNTIME_DIR

         echo 'Execution directory inaccessible' >&2
         exit 1
}

echo hello woltf

```



- 删除at任务
```bash
at -d <job number>
```

>[!warning]
> 注意：一次性计划任务无法修改，只能删除


- 指定at任务的优先级：范围是从a到z，a优先级最高，z优先级最低，优先级高的任务优先执行
```bash
1034 at -q a 16:10

1035 at -q z 16:10
```

- 每定义一个at任务，都会在`/var/spool/at`目录下创建一个可执行文件,`at -c`看到的at任务详细信息实际上看到的就是这个文件中的内容
```bash
[root@rhel at]# at 16:03
warning: commands will be executed using /bin/sh
at> touch file{1..10}
at> <EOT>
job 2 at Sun Jul 20 16:03:00 2025

ll /var/spool/at
total 4
-rwx------. 1 root root 3972 Jul 20 16:00   a0000201bdcf83
-rw-r--r--. 1 root root 0 Jul 20 15:59 file1
drwx------. 2 root root 6 Jul 20 15:59  spool

```

### 相关问题
---

**1. 如果定义的时间已经过去了，at任务还会定义吗？**

>[!note]
>- 如果指定的时间在当前系统时间之前，例如系统时间为`18:40`，但是任务时间为`17:50`，那么系统会认为在下一个时间来执行该任务，即第二天的该时间执行任务。
>- 但是注意，如果指定的时间精确到了年月日时分秒，那么此时执行命令就会报错，因为已经超过了当前的系统时间，无法再次指定任务

---
**2. 如果定义的时间为20250720的下午6点，然后在5点59分的时候系统关机了，在6点01分才开机，那么这个at任务会执行么？

>[!note]
>答：会执行。并且是在开机的时候立即执行

---
**3. at通过文件的方式可以实现非交互式创建，如果这个文件没有x权限的话，at任务还会实现吗？**

```bash
ll at.sh
-rw-r--r-- 1 root root 28 Jul 20 16:02 at.sh

[root@node1 ~]# at 16:03 < at.sh
warning: commands will be executed using /bin/sh
job 9 at Sun Jul 20 16:03:00 2025
```

>[!note]
>答：会执行。at任务跟源文件没有关系，实际上是读取文件中的命令然后在/var/spool/at目录下创建一个可执行文件

---
**4. at是管理工具，如果没有at能否定义一次性计划任务？**

```bash
[root@CentOS ~]# systemctl status atd.service
● atd.service - Job spooling tools
   Loaded: loaded (/usr/lib/systemd/system/atd.service; enabled; vendor preset: enabled)
   Active: active (running) since Thu 2026-11-05 18:56:33 CST; 32min ago
 Main PID: 1381 (atd)
    Tasks: 1 (limit: 24596)
   Memory: 468.0K
   CGroup: /system.slice/atd.service
           └─1381 /usr/sbin/atd -f
```

>[!note]
>答：可以的。at只是管理工具，真正干活的人是atd服务



### 限制一次性计划任务

- at任务有2种方式来限制：
	- 白名单 **`/etc/at.allow`**：此文件中的用户可以使用at任务，除了白名单里面的用户 其他的用户都拒绝
	- 黑名单 **`/etc/at.deny`**：此文件中的用户无法使用at任务
    
>[!tip]
>如果一个用户同时存在于黑白名单，哪个优先级高？ 白名单



## 2.周期性计划任务

### 基本使用

- 核心工具：`crontab`
- 设置周期性计划任务，执行如下命令，同时也可以编辑周期性计划任务
```bash
crontab -e 
```

执行后会打开一个`vim`编辑器，里面设置周期性计划任务的内容，编写完成后，和正常文本保存一样，保存退出即可。

>[!tip]
>如果文本编写有错误，无法继续执行后续命令，会报错。

- 时间格式如下，有数值的填写对应数值，没有数值的，用`*`来替代
```bash
* * * * *
```

>[!important]
>分别对应分，时，日，月，周
>
> - 分钟：0 - 59
> - 小时：0 - 23
> - 日：1 - 31
> - 月：1 - 12
> - 周：1 - 7


- 时间的常见写法
	- **`x-y`**:在x到y这个时间之中
	- **`x,y`**:在x时间和y时间
	- **`*/x`**:每隔x个时间

- 查看计划任务，执行如下命令
```bash
crontab -l
```


>[!note]
>下面给几个案例

**1. 在每天的的下午两点开始，一直到五点钟，执行`echo hellp`命令**

- 即在在2点10分、3点10分、4点10分、5点10分执行`echo hello`命令
```bash
10 2-5 * * *  echo hello
```


**2. 在12月12日这1一天，上午8:15清理`/tmp`下的所有临时文件以及在下午的17:15清理`/tmp`下的所有临时文件**

```bash
15 8,17 12 12 * rm -rf /tmp/*
```


**3. 每隔五分钟，执行命令 echo hello**

```bash
*/5 * * * * echo hello
```

 


### 批量创建与文件介绍

>[!important]
>上面看到`crontab`是属于一种交互的命令，如果要批量对很多主机来创建计划任务，那么就会很麻烦

- 可以通过管道来实现批量创建
```bash
echo "*/5 * * * * echo hello" | crontab
```


- crontab的任务如果有输出的性质，默认是不会直接显示在屏幕上，而是在日志文件中显示`/var/log/cron`
```bash
tail -f /var/log/cron

Jul 20 16:52:01 node1 CROND[2492]: (root) CMDEND (echo /etc/crontab_root)
Jul 20 16:52:01 node1 CROND[2499]: (user) CMD (echo user)
Jul 20 16:52:01 node1 CROND[2494]: (user) CMDOUT (user)
Jul 20 16:52:01 node1 CROND[2494]: (user) CMDEND (echo user)
Jul 20 16:52:01 node1 CROND[2504]: (user) CMD (echo /etc/crontab_user)
Jul 20 16:52:01 node1 CROND[2493]: (user) CMDOUT (/etc/crontab_user)
Jul 20 16:52:01 node1 CROND[2493]: (user) CMDEND (echo /etc/crontab_user)
```

>[!tip]
> 对于crontab任务来说，用户定义了计划任务，在`/var/spoo/cron`目录下会创建一个和用户同名的文件，这个文件的内容就是计划任务的内容

- 每一个用户创建的计划任务会存放在对应用户名名字的目录中
```bash
[root@webserver cron]# pwd
/var/spool/cron
[root@webserver cron]# ls
root  user1
```


### 限制周期性计划任务

crontab任务的限制：
- 黑名单：**`/etc/cron.deny`**，限制名单中的用户
- 白名单：**`/etc/cron.allow`**，允许名单中的用户

>[!important]
>- 如果只有`/etc/cron.deny`，那么名单中的用户被拒绝，其他用户都被允许
>- 文件`/etc/cron.allow`一旦存在，除非名单中有的用户，其他用户全部拒绝，即使`/etc/cron.deny`中清空，仍然是如此，黑名单默认被忽略


文件中每一行写一个用户名
```bash
zhangsan
lisi
wangwu
```

> [!tip]
> 黑白名单冲突，白名单优先级更高
